# Bansho — CSS 3D 过渡感 设计意图书

> 产品负责人 2026-08-11 提出并当场收敛。本文只记**意图、边界与理由**；
> 排期在画布转向 V1 之后（理由见 §5）。

---

## 0. 从哪儿来，到哪儿去

**起点（脑洞原话）：**
> 「按照现在的架构，是不是连黑板都可以做真正的 3d 变换。。就是直接在 three.js 里面
> 用真实的镜头 + 空间 来上课！」

**收敛（同一轮，产品负责人自己判的）：**
> 「我觉得是 **注意力引导 + 空间变化产生的过渡感**。。所以确实 css3d 应该就够了」

**这句收敛就是需求本身**，也是这份文件存在的理由：要的是**过渡感**，不是三维物体。
判据清楚了，方案就跟着清楚——**CSS 3D，不是 three.js**。

## 1. 为什么这个想法在架构上说得通（不是白日梦）

- **`seek(p)` 从第一天就是纯映射、宿主无关**（D2）。当初选它而不是 `play()`，
  图的就是「任意时间源可驱动」。渲染层换不换，引擎层**一行不用改**。
- **镜头已经是纯折叠**：`stageStateAt(schedule, t)` 返回 `{camera, panelOffsets}`。
  加透视之后 `z` 从「缩放」变成「距离」，**折叠本身不动**。
  （Van Wijk 弧长参数化本来就出自三维相机运动研究。）
- **画布转向恰好产出 3D 需要的输入**：每个内容步是一个有 `(x,y,w,h)` 的盒子——
  往空间里贴 quad 需要的正是这个。流式布局给不了。

## 2. 定死的边界：**纵深只在过渡里出现，稳态永远正对**

这条是我提的，产品负责人的判据直接推出它，**它是本方案的可读性保险**：

- **被讲的板必须正面朝向读者、字不斜。** 那一刻它的工作是**被读**，
  而透视对可读性是**负的**。
- **只有切换的那一刻**（板 → 板、focus → overview）透视才登场，
  承担「从这块到那块」的空间连续性。
- 于是负作用被关在几百毫秒里，买到的连续感是全程的。

**推论：`rotateY` 之类的角度不是一个可长期停留的状态，是过渡函数的中段值。**
如果将来有人想让板"常年带点角度"，那是另一件事（属于书写仿真的
`歪斜` 家族，见 canvas-pivot brief §7），不要和这条混为一谈。

## 3. 为什么 CSS 3D 够、three.js 不划算

**CSS 3D 几乎免费**：舞台现在就是**一个 transform**
（实测 `matrix(0.242512, 0, 0, 0.242512, …)`）。加 `perspective()` +
每块板的 `rotateY()` 即可。**DOM 文字、SVG 墨迹、MathML、测量宿主、六个 factory
全部原样保留。**

**three.js 要重写三样东西**（下面每条都是我这几轮实测过渲染层才敢说的）：

| 现在 | WebGL 里的代价 |
|---|---|
| **真 DOM 文字**（浏览器换行 + 字体回退，中文手写体 `HanziPen SC`）；**整套墨迹几何靠量实际渲染位置** | SDF 文字中文图集巨大且丢换行；渲成贴图一放大就糊——**而放大恰恰是镜头的意义**；`CSS3DRenderer` 能保住 DOM 文字，但它不参与深度缓冲，其实不是真 3D |
| **揭示 = `clip-path: inset(0 54.09% 0 0)` 从左往右擦**（实测值） | 没有这东西；要换裁剪平面或着色器 alpha —— 可行，但**六个 factory 的揭示策略逐个重来** |
| **公式 = MathML**（真 DOM 树，所以能从左往右擦） | 没有 MathML，整条路重做——**而这正是刚修好的「太工整」那块** |

**换句话说：CSS 3D 是加法，three.js 是换产品。** 后者只有在
「真的在一个教室里、可以走动、将来上头显」时才值得——那时要重新想
「课」在空间里是什么，不是换个渲染器的事。

## 4. 纵深唯一真正新增的教学动作（值得单独记）

**「这块板退到后面去，那块推到前面来」** —— 用**距离**表达"现在讲哪个"：

- 比**擦掉**温和（内容还在，只是退居次要）
- 比**并排**有层次（并排是平权的，前后是有主次的）

这是 2D 做不到的，而且它是**教学动作**不是视觉特效——符合这个 mode
「舞台调度必须是表达」的一贯纪律。若 CSS 3D 只实现一件事，应该是它。

## 5. 排期：**V1.5**，插在 V1 与 V2 之间（2026-08-11 拍板）

产品负责人先提「把 V2 的目标直接调整成这个」，我提了反对意见并被采纳：
**V2 是一个语义包**（`@at` + 碰撞 + `frame-board`），拆开会塌——
`@at` 让 agent 能声明位置，声明就会撞；撞了必须**看得见**（预览）
和**被报出来**（自检），而这整套正是 D-3「auto-erase 删除、房间永不悄悄拆板」。
只做 `@at` 不做碰撞 = 让 agent 摆版面却没有任何反馈；
只做碰撞不做预览 = 老师流程的第 3 步（想象占位区域）根本不存在。
**C3 那轮已经踩过一次「语义包拆开」的坑**（面积+擦除+笔记）。

而 CSS 3D 是**纯加法**——零方言、零契约、只在过渡的几百毫秒里改 transform，
不与任何一期争夺同一块代码。于是定为**插队而非替换**：

| 期 | 内容 | 用户能看见什么 |
|---|---|---|
| **V1**（进行中） | 盒模型 | **看不见任何新东西**（地基） |
| **V1.5** | 本文：可 3D 变换的黑板 | **立刻能看见空间感** |
| **V2** | `@at` + 碰撞 + 预览（**不拆**） | agent 真的会摆版面了 |

插队的实际理由：**V1 落地后你手上仍然是"四页教科书"**——内容有盒子了，
但还没人会摆，要等 V2 才好看。CSS 3D 是这条路上**最快能看见效果**的一段，
正好填上这个空窗。

**但它确实要等 V1**：CSS 3D 依赖盒模型才干净（板必须是独立的变换单元），
而且 V1 正在重写渲染挂载，现在动会打架。

### 5.1 分层边界（产品负责人定的形态，值得钉死）

> 「css3d 提供的是**可以 3d 变换的黑板**，应该不影响的。」

**V1.5 交付的是能力，不是玩法。** 板成为可被三维变换的单元、过渡有透视；
**哪些教学动作使用它**（退到后面 / 推到前面 / `@bring` 转过来）
由 V2 的舞台指令去消费。

这条分层同时保证两期**不碰同一块代码**：V1.5 只动渲染挂载，
V2 只动方言与折叠。

## 5.2 视差开关（产品负责人 2026-08-11 追加，随 V1.5 一起做）

> 「你可以在 viewer 上给个小开关，允许鼠标模拟轻度的摇晃，获得一个小幅度的晃动感～
> 哈哈哈 这样就可以让用户直接感知到了」

**它不只是个玩具，它是这一期的探针。** 纵深有没有真的建立，本来是一句需要相信的话；
鼠标一晃，**视差自己会跑出来**——真三维会产生前后位移差，假透视（只是画了个斜面）
一晃就穿帮。**验证的人和体验的人看到的是同一件事**，这正是这个 mode 一贯要的
「不能靠想象判断视觉」。

**三条必须提前钉死，否则它会咬到别的东西：**

1. **视差绝不进 canonical。** 它是**观看姿态**，和用户滚轮/拖拽同族，
   与 `stageStateAt` 折叠出的导演镜头**必须是两层**。混进去就是让"鼠标在哪"
   改写时间轴——R8 当场破。
2. **它不能污染测量（G8-J 族）。** `getBoundingClientRect` 受 transform 影响、
   布局值不受。视差必须写在**舞台之上的一层**（或明确排除在测量漏斗的基准之外），
   否则鼠标一动，回指墨迹的锚点就漂。这条与书写仿真的歪斜是同一个家族问题
   （见 §6-4）。
3. **默认关，幅度小，可关到 0。** 与瑕疵旋钮同族纪律。且必须尊重
   `prefers-reduced-motion`——对前庭敏感的人，持续跟随鼠标的画面是真的难受。

**顺带的好处：** 它给了 V1.5 一个**不依赖任何方言**的验收方式——
不用等 V2 有人会摆版面，晃一下就知道纵深成没成立。

## 6. 开工前要答的（不 gate V1）

1. 过渡的**触发面**：哪些舞台动作带透视？（板→板切换、`@overview` 出入、
   `@bring`——`@bring` 用**转过来**而不是平移过来，可能是最自然的一个）
2. **可访问性**：`prefers-reduced-motion` 下退化成什么？（我倾向：退化成现有的 2D 过渡，
   而不是瞬切）
3. **性能**：透视会给整个舞台建合成层。C1 当初**刻意没加** `will-change: transform`
   （4300px 高的板栅格化成本真实）——透视是否重新打开这个问题，要实测。
4. 与**书写仿真**的歪斜怎么共存：两者都写 transform，谁在外层、会不会互相污染测量
   （G8-J 的家族问题：`getBoundingClientRect` 受 transform 影响，布局值不受）。
