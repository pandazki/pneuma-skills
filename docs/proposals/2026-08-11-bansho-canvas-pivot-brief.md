# Bansho —「画布 + 内容块」转向 设计意图书

> 产品负责人 2026-08-11 提出并拍板。本文只记**意图、决定与理由**，不定方案——
> 方案交 architect。原话逐条保留，因为每一句都比我的转述准。
>
> **这份文件推翻了三条已定结论**（见 §5），其中两条是我自己写的。

---

## 0. 触发这次转向的那句话

> 「你现在内容的写法。就是假设黑板只能从上往下写。。跟在读教科书没有任何区别。」

四块板各自从上往下写满 = 四页教科书。舞台层给了 agent **更多的板**，
但没给它**布局**——内容仍然只有一个自由度：文档顺序。

真黑板不是这样用的：图画在右边空白而左边继续推、定义写在角上一直留着、
两栏并排对比、先留一块空讲到了再回来填。**这些都不是「下一个位置」，是「选位置」。**
而且是**选择性的**——不是每次都摆，是内容值得的时候才摆。

配图证据（产品负责人截图）：那块 graph 之所以有效果，恰恰因为它是**唯一一处
「内容自己决定了形状」**的地方（两条分支并排，10 与 100 的对峙是画出来的）；
它周围的一切、包括后面那张过大的图表，都被同一条规则摆着——按序、从上往下、占满板宽。
**图表过大不是图表的问题，是版面只有一个自由度**：除了「下一段」没有别的位置可说，
尺寸也就只能是默认值。

## 1. 老师真实的书写流程（原话，五步）

> 1. 我先构思写什么（可能不止一个，比如我要写 2 段话+1 个图+一个大标题标准重点）
>    （也有可能是对历史内容的补充、强化、修改）
> 2. 我先看一眼现在的黑板已有的内容
> 3. **想象一个占位区域**，我写完这个内容之后，结果会变成什么样子。
>    （如果明显空间已经不合理了，考虑擦除一些内容）
> 4. 真实去写上内容
> 5. 尝试对比预期和实际的差距，大致重叠就完成。
>    （如果超出了范围，或者导致有大的变化，例如换行到下个 board，就重写，
>    **这个重写不用体现在流程中，这属于播放动画的设计阶段，并非直播**）

**第 5 步括号里那句是本轮最有价值的一句。** 它解开了我此前拒掉的东西：

- 我拒绝过「试算落点」，理由是「诚实的试算不可能便宜、便宜的试算不可能诚实」。
- 按这个流程**根本不需要试算**：写下去、看结果、不对就重写。
  测量就是真实构建，没有预测，也就没有误差。
- 而重写之所以免费，正因为**创作不是直播**。

**可计算的边界：已被真正播放过的最高水位线。** 水位线以下是已示内容，
append-only 纪律照旧；水位线以上从来没人看过，随便改。流式那条路不破。

## 2. 预览必须是「贴图」而不是「渲染」

> 「我这里说的所有的意图，都是用 tool call 调用由 viewer 提供的 api，
> 得到一个『**脑内渲染的占位图/示意图**』，用**半透明色块**去填充 + 截图，让 AI 来看。」

关键推论（产品负责人点破的，我原先没看到）：

> 「这个前提是你的整个布局，**不能再是这样的 html 流自然布局**，
> 而是要用**画布 + 贴内容块**的形式来做了。」

**这个 API 只有在画布模型下才可能存在。** 流式布局里「这块会落在哪」没有独立答案——
位置是它之前所有内容的后果，不放下去就不存在。画布模型里位置是**声明**的，
预览不必渲染内容、只需画矩形：**又便宜又诚实**。
唯一的不确定是内容会不会撑破自己的框——那恰好就是第 5 步要对比的东西。

## 3. 三个拍板决定

**D-1 区域，不是自由坐标。**
> 「人也是大致分区」

板相对的语义区域（左栏 / 右上 / 角落），不是像素坐标。自由坐标会把 agent 拖回像素算术。

**D-2 尺寸硬、后果软；看完渲染再调。**
> 「可以用软的方式，但是**渲染回来看的时候可以调整**」

声明即是框；撑破了系统**如实回报**而不是悄悄重排；调整发生在看过之后（第 5 步）。

**D-3 自动擦除交给 agent —— 碰撞取代它。**
> 「写满怎么擦。。应该是 Agent 自己。。（而且如果他视而不见，下一步预测书写 intent 的时候，
> **应该会重叠**），然后写入被 **viewer 的自检 api 警告**，他看到警告会知道自己调整。」

这比原来的 auto-erase 干净得多，而且**修好了第一位真实作者最尖锐的那条抱怨**：
「一块板可以被结构性拆掉，而 `check-board` 一片绿——它审的是墨迹，不是房间。」

新机制里房间**永不悄悄拆板**：满了就是重叠，重叠**看得见**（预览里）、
**被警告**（写下去之后自检报），agent 自己决定擦谁。
auto-erase 当初是为「agent 不管空间」服务的——那条前提没了，它大概率整个不该存在。

## 4. 块内仍是流式（我提的，未被否）

**块的位置与尺寸由声明决定；块内部一段话怎么换行、列表怎么堆，仍交给浏览器。**

买到两件事：(i) 墨迹几何（圈/划/荧光按文字实测位置量）**块内完全不变**；
(ii) 换行与字距那种像素算术**仍然不归 agent**——第一位作者垫散文挤标题、
垫的那段自己翻页、级联毁掉后面所有断点、烧掉二十分钟的事不会重演。

## 5. 被本轮推翻的三条已定结论

| 原结论 | 出处 | 新结论 |
|---|---|---|
| **「agent 永不思考空间，空间调度归系统」** | feasibility §1.4 | **agent 声明空间意图（板相对区域），系统做全部算术并如实回报。** 仍禁止：像素、行数、为了断行而注水 |
| **候选试算「永久拒绝」** | snapshot design rev 2 §7.5 | 在画布模型下重新成立，且不是模拟器——预览画的是**声明**，不是预测 |
| **auto-erase 是「继续讲下去的默认物理」** | feasibility §1.5 | 由 agent 决策；碰撞 + 自检警告取代之（D-3） |

## 6. 迁移代价（我的评估，交 architect 复核）

**活下来：** `Revealable`/`seek(p)`（揭示与布局正交，这是当初 D2 的红利兑现）·
整套方言 · 公式 / chart / graph 工厂 · **镜头**（画布上比流式上更自然）·
擦除（擦一块区域比擦一段文档流更合理）· 笔记视图（按文档序线性化、忽略位置）。

**要重做：** `engine/layout.ts` 的归属折叠——现在是「按序填、放不下换下一块」，
那正是「四页教科书」的成因；要变成「解析位置声明 → 得到矩形」。

**必须有意处理（2026-08-11 两次修订，最终形态见下）：**

- 我最初写「三块基线板每条墨迹坐标都会变」，并据此估了迁移代价。architect 复核后
  我实测确认**这句是错的**：三块仪器板**一个舞台动词都没有**
  （`@board`/`@turn`/`@erase`/`@focus`/`@overview` 命中全为 0），全是单条长卷。
- 但随即产品负责人裁了那个读法歧义（设计稿 §16-6），**结论是长卷也画布化**——
  于是那句话**因为另一个原因重新成立**：三块仪器板全部要重奠基。

### D-4 长卷也画布化（2026-08-11 拍板）

> 「长卷也画布化。。长卷也可以有点斜 / **分成几个短文本框来引入不规则感** 嘛」

**没有两种板了。** 长卷不是「另一种布局模式」，只是一块很高的板，走同一套区域方言。

后半句是独立的产品诉求，别当成随口一提：**即使只有一块板、不换板，
把内容切成有位置的块本身就是反教科书的**。它与 §7 的瑕疵是同一诉求的两面——
一个是**结构**上的不规则（块的位置与尺寸），一个是**笔触**上的不规则（歪斜与扰动）。

**代价必须讲在明处：**

- **「未声明位置的板逐字节退化等价」这道门不再成立。** 它是 C1/C2/C3 每一期
  用来证明「没弄坏老东西」的安全绳，从此不能再用在长卷上。
- V1 因此**没有「结构切、行为零变化」的中间态可走**了。
- 三块仪器板**全部重奠基，而且必须是有意的、留证据的**：同会话同探针
  采 pre/post 两侧、把差异说清楚，**绝不顺手刷新**——
  用法与陷阱见 `modes/bansho/harness/layout-baseline/README.md`
  （那份文档已经记了「当墨迹本该移动时，门的问题从『有没有动』变成
  『是不是恰好该动的动了』」，正是这次要用的形态）。
- 换来的是概念统一：一套模型、一套方言、一个折叠，不再有特例分支。

### D-5 命名（2026-08-11 拍板）

- 放置动词：**`@at`**（「语意连贯清洗即可」——短，与 `@erase`/`@turn` 同语域）
- 预览动作：**`frame-board`**（「别太抽象」——与 `check-board`/`glance-board` 结构成对）

## 7. 书写仿真（同一轮提出，落法待布局定稿后再谈）

> 「影响真实感的，是**瑕疵**。例如意料之外的错别字（涂掉再写旁边），
> 例如粉笔随机周边的点击，没有那么干净的黑板。书写区域的四边形随机旋转和形变
> （我们写字有时也会斜）。这些程度都**可以配置，调成 0 就是干干净净**的状态。
> 这个跟你划线模拟的那种不直的效果是一类的，都是在做**书写仿真**。」

**我提的切分（产品负责人未否，也未细谈）：** 里面有两类东西，代价完全不同——

- **只花像素的**：粉笔屑、板面不洁、**擦过留残影**、整板轻微歪斜、每行基线漂移。
  不占时间、不进 canonical、不改变任何人读到的内容 ⇒ 适合做成**一个强度旋钮，0 = 干净**。
  （「擦过留残影」是白捡的：零时间成本，教学上还对——你能看出这儿曾经有东西。）
- **要花时间的**：错别字、涂掉、旁边重写。占时间轴、改变读者读到的字、
  scrub 回拖必须每次一样，还牵扯笔记视图留不留那个错字。

  **我的判断：错别字应是作者用的动词，不是引擎随机撒的。** 随机撒会落在关键术语上——
  可能正好涂掉要讲的那个词，那是教学伤害。作者写的错字是**修辞**（故意写错、当场发现、
  划掉重写 = 一个教学节拍）。折中方案：引擎按内容定种子挑受害者，但**限定低风险词**
  （非高亮、不在公式里、不是后面要回指的锚点）——这些引擎都知道。**待产品负责人选。**

**两条硬约束（提前记下，别让实现者现踩）：**

1. **墨迹要跟着变形走。** 圈/划/荧光按文字实测位置量。整板歪斜免费（墨迹同坐标系一起歪）、
   每行漂移可行（量到的矩形跟着动）；**每行独立旋转**会让轴对齐的墨迹层跟不上，要单独设计。
2. **默认值一开就动测量仪器。** 所以扰动**必须定种子**（同一份讲稿永远同一份瑕疵），
   且默认强度是个要拍板的数。
