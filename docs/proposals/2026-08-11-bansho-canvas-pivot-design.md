## §0 一句话方案（rev 2 措辞更新）

画布 = **归属折叠升一个粒度**：现役折叠把内容分给「板」，转向后分给
「板 × 区域」——**今天的板恰好是"每板一个 `full` 区域"的特例**，没有新机制，
只有既有折叠的推广。（rev 2）**每个内容步是画布上的一个绝对定位盒子**：
盒内换行仍归浏览器，盒间的 (x, y) 全部由折叠算出——这是「不能再是 html 流
自然布局」的字面兑现，长卷与四板墙同一套物理。agent 用新方言动词 **`@at`**
声明板相对的语义区域；**声明即是框**（尺寸硬），内容撑破框或压住别人的墨迹时
**如实回报、绝不悄悄重排、绝不替人擦板**（后果软，D-2/D-3）；新 viewer 动作
**`frame-board`** 把候选声明画成**半透明框叠在真板截图上**交还 agent——
它画的是**声明**，不是预测，所以又便宜又诚实。auto-erase 整个删除：房间剩下的
唯一自动行为是「把笔带去干净的板」（fresh → wiped），连这一步都无板可给时，
房间**停止决定**，写入原地下溢、碰撞可见、自检报警、agent 自己决定擦谁。

## §1 问题与力（用本项目的话重述）

- **版面只有一个自由度是病根。** 四块板各自从上往下写满 = 四页教科书；
  图表过大不是图表的问题，是除了「下一段」没有别的位置可说，尺寸只能是默认值
  （brief §0）。舞台层给了更多的板，没给布局。
- **（rev 2）一栏到底本身就是病，与几块板无关。** 产品负责人对长卷的裁决
  （「分成几个短文本框来引入不规则感」）把反教科书的要求下沉到单板：
  **即使没有换板，内容也应当能以若干独立的短盒子落位**。不规则感有两半：
  结构半（哪块盒子放哪——本设计）与质感半（歪斜/漂移/粉笔屑——书写仿真，
  另一份设计）；两半共用同一个前提：**块必须先是盒子**。
- **要服务的节奏是五步循环**（brief §1）：构思 → 看板（`glance-board`）→
  **想象占位区域**（本设计的 `frame-board`）→ 真写 → 对比预期与实际，
  不对就重写。**重写免费，因为创作不是直播**——可改边界 = 已被真正播放过的
  最高水位线；水位线以下 append-only 纪律照旧，以上随便改。流式那条路不破。
- **预览必须是贴图不是渲染**（brief §2）：流式布局里「这块会落哪」没有独立答案，
  画布模型里位置是声明的——预览只画矩形，唯一的不确定（内容撑不撑破框）
  恰好是第 5 步要对比的东西。这就是 snapshot design §7.5 拒绝 dry-run 的前提
  为什么是 flow-specific 的：那时「落哪」需要猜高度，现在「落哪」是读声明。
- **位置是选择性的。** 不是每次都摆，是内容值得的时候才摆（brief §0）——
  未声明的内容走确定性的默认堆叠（§2.2），方言的增量是**多一个自由度**，
  不是强制每笔申报。
- **成功判据：** agent 能说出「图在右边、左边继续推」「定义停在角上」「两栏对比」
  「留一块空回头填」四个动作（brief §0 点名的四个）；说错了看得见（预览）、
  写坏了被告知（自检）、房间永不悄悄拆板；（rev 2）长卷上的讲稿能自然长成
  「若干短盒子」而不是一根柱子。

## §2 模型：盒子、区域、笔（rev 2 重写——总画布化）

### 2.1 四句话模型

1. **每个占空间的内容步是一个盒子。** 盒子的 (x, y, w) 由折叠算出（§7），
   h 是实测；盒内是普通文档流（换行、对齐、KaTeX、chart 全在盒内，§9）。
   零占位步（回头标注、图层）住进它们的家盒（既有 home 规则原样）。
2. **区域之于板，恰如板之于墙。** 每块板被封闭词表（§3.2）划出命名区域；
   区域是盒子的**归属与框**：具名区域给盒子 x/w 与硬预算，`full`（缺省）
   是房间自己的流。区域各有 run 序列（两次擦除之间的盒子集），与现役折叠的
   板 run 完全同构——**今天的板 = "每板一个 `full` 区域"的特例**。
3. **笔永远站在恰好一个区域里**：`@at` 在板内移笔，`@turn` 在板间移笔，
   内容步落进笔所在区域的 open run。
4. **（rev 2）长卷 = 同一模型上的一块高板。** 不是第二种布局模式：同一折叠、
   同一盒子、同一方言、同一碰撞谓词；差别只是参数——它的面无下界
   （H = ∞ ⇒ 纵向永不 burst、永不走位），y 分数词在无界轴上无定义（§3.2）。

### 2.2 默认堆叠（`full` 的物理，rev 2 钉死）

- **`full` 的下一个盒子落在该板的书写前沿（front）**：
  `front = max(站立盒子的 bottom)`（该板上、含所有区域；无站立内容 = 0）。
  房间的流从不主动压别人的墨迹——「继续写」永远写在**一切站立物之下**。
  这不是避让式重排（没有任何已放置盒子被移动），是「按序往下写」在
  多区域世界的唯一诚实推广。擦除使 front 回退（被擦的不再站立）——
  长卷上 `@erase` 后新章回到顶部，与现行「清场开新章」语义一致。
- **具名区域的下一个盒子落在该区域自己的游标处**（frame.top + 已站立高度）
  ——作者的框，作者的游标，作者的后果（碰撞/burst 如实回报）。
- 未声明的板只有 `full` 盒子 ⇒ front = 自己的底 ⇒ 行为与今天的按序堆叠
  同构（y 的算术模型见 §7.5，与 CSS flow 的差异走 §12.2 的重奠基协议）。

### 2.3 房间还替你做什么、不再替你做什么（D-3 的机制面）

| 房间的行为 | 转向前 | 转向后 |
|---|---|---|
| 未声明内容填板 | 按序填，放不下换下一块（三级策略） | **保留前两级**：fresh → wiped（§7.3）；长卷（count=1）无处可走也无需走（H=∞） |
| 全满仍写 | **合成 auto-erase**，擦最早写满的 | **删除**。笔留在原地，内容继续向下**下溢**（burst，越过板底边、看得见、被报警）；agent 自己决定擦谁 |
| `@turn` 满墙 | 房间擦最早写满的（§7.6-Q1） | **惰性 + 响亮 finding**（§5.5）——房间不再有权选受害者 |
| 具名区域写满 | （不存在） | **永不走位、永不擦**：内容下溢出框（burst），如实回报（§4） |
| 写进别人的墨迹 | （不可能——流式不重叠） | **允许发生**：碰撞可见（预览 + 板面）、自检报警（§5），房间不阻止也不修复 |

「房间永不悄悄拆板」由此成为结构性质：**转向后不存在任何一条自动擦除路径。**
`autoEraseBefore`、`boardAutoErased` 通知、glance 的 `pen.nextOverflow`
auto-erase 分支、`erased.byAuto` 字段全部死亡（台账 §12.4）。

## §3 方言：`@at`（D-1——区域，不是坐标；名字已裁定）

### 3.1 形式

```markdown
@at right

```chart 增长率
…
```

@at top-right "那个定义"
```

- **`@at <region>`** — 独立成行的舞台指令，与 `@erase`/`@turn` 同族。
  笔走到**当前板**的命名区域。（rev 2）后续语义分两种面：**有界板**上
  该区域已有站立内容则**恢复**（接着游标写）；**长卷**上 bare `@at` 一律
  **开新置放**（episodic，§3.6——长卷的置放是「前沿处的又一个短盒子」，
  不是固定格子的续写）。
- **`@at <region> "锚文本"`** — 锚定形：引文按既有规则（就近向上、单步内、
  公式零字符）解析到某个内容步；有界板上笔走到**那个步所在板**的命名区域，
  长卷上笔走到**持有该步的置放**（恢复它——跨距回填与并栏对照的出口，§3.6）。
  **一切跨板/跨距引用锚内容、不锚板号**，既有推论原样适用。
  **锚不中时的退化钉死（`@focus` 同族）**：bad-step badge + `refUnresolved`，
  **笔不动**（后续内容留在原区域）。
- 作用域：**pen-scoped**——`@at` 之后的内容步都落在该区域，直到下一个
  `@at` / `@turn` / 文档结束（fork 讨论与 block-scoped 备选见 §3.4；
  rev 2：产品负责人已随 ① 认可推荐，A 定案）。
- 时间轴：`AtStep` 进 `Step` union，占 schedule 独占时段（G1），计划为恰好
  一个走位单元，`naturalDuration = DurationConstants.place`（新常数，初值取
  `turn` 现值，T5 终校表管辖；实现者从 `duration.ts` 读，不发明数字）。
  无 revealable——`makeSeek` 既有 unpaired dispatch-nowhere 路径（镜头步/turn
  同款）。镜头分类与 erase/turn 逐字相同（**不是写**，锁存姿态骑过它的窗口，
  P1-3 家族）。不可发声（房间动作没有台词）。笔记投影忽略。
  G6：srcSpan = 自己那一行。

### 3.2 区域词表（封闭集合，v1 = 9 词）

设板的内容盒（去 padding）为 W × H，区域间距 `REGION_GUTTER = 24` board px
（新常数；板间既有 `PANEL_GAP = 32`）。矩形是 (W, H) 的纯函数，钉死如下
（`g = REGION_GUTTER`，`w2 = (W−g)/2`，`h2 = (H−g)/2`）：

| 词 | x | y | w | h | 老师的话 |
|---|---|---|---|---|---|
| `full` | 0 | 0 | W | H | 整块板（缺省，无需声明） |
| `left` | 0 | 0 | w2 | H | 左栏 |
| `right` | W−w2 | 0 | w2 | H | 右栏 |
| `top` | 0 | 0 | W | h2 | 上半 |
| `bottom` | 0 | H−h2 | W | h2 | 下半 |
| `top-left` | 0 | 0 | w2 | h2 | 左上角 |
| `top-right` | W−w2 | 0 | w2 | h2 | 右上角 |
| `bottom-left` | 0 | H−h2 | w2 | h2 | 左下角 |
| `bottom-right` | W−w2 | H−h2 | w2 | h2 | 右下角 |

- **尺寸随词而来**（半宽栏 / 全宽带 / 四分之一角），没有独立的尺寸轴——
  「图表过大」的修复路径就是选一个更窄的词（`@at right` 的 chart 以半宽渲染）。
- **`@at full` 合法且必要**（角落驻留后回主流的唯一出口）：回到房间的流
  （下一个盒子落在 front，§2.2）。**物理跟着词走，不跟进入方式走**——
  `full` 永远保有房间的流物理（有界板上溢出换板、front 堆叠，§7.2），
  八个具名词永远 burst；显式说出 `@at full` 不会剥夺这块板的走位。
- **（rev 2）词的统一读法：词说「多宽、贴哪边」，面说「从哪儿起」。**
  有界板的面是固定的 ⇒ y 由表中分数给出；长卷的面无下界 ⇒ 纵向分数词
  （`top`/`bottom`/四角）**无定义**，判 BadStep（理由见 §3.6——不是长卷的
  特权分支，是无界轴上的类别错误）；`left`/`right`/`full` 在长卷上照常，
  y 锚在前沿（§3.6）。
- **词不在表**（如 `@at middle`）：parse 层 BadStep，消息列出该面全部合法词
  （与长卷消息同一教学姿态）。
- **词表生长规则（钉死）：只加词，永不加数字。** `center`、三分横带、
  锚定相对位（`below "锚"`）是已知候选，全部 deferred（§16-3）——
  一处真实需求再现才铸词（snapshot design「一处再现」原则）。
- **已知的表达力缺口（记录在案，不 v1 修）：** 「横贯顶部的大标题 + 底下两栏」
  组不出来——`left`/`right` 从 y=0 起，会压住横幅的墨迹（诚实碰撞）。
  v1 的出路是 `top` 横幅 + `bottom-left`/`bottom-right`（中带留白，
  老师也浪费板面），或标题进栏内。这个缺口是 `center`/三分带的立项证据位。

### 3.3 刻意不可说的（与可说的同等重要）

像素、百分比、任何数字坐标或数字尺寸 · 板号（跨板永远走锚）· 行数 ·
「让它恰好放下」一类的 fit 强迫 · z 顺序 /「写在那上面」的叠写意图 ·
移动或缩放已站立的内容（墨迹是物质——错了就擦，或在水位线之上重写）·
**「哪儿有空写哪儿」**（请房间替你选位置，恰恰是被删掉的那套物理；
看板和选位置从此都是你的事）·（rev 2）**歪斜与抖动**（不规则的质感半
归书写仿真的配置旋钮，不是方言词——作者摆盒子，房间摇盒子）。

反注水纪律**原样存活且更强**：为了操纵折缝给段落垫料，从「跟物理打架」变成
「彻底没必要」——你不喜欢内容落的地方，用一个**词**移它，不用一句坏散文。

### 3.4 作用域 fork：pen-scoped（rev 2：已定案 A）vs block-scoped（备档）

| | **A. pen-scoped（定案）** | B. block-scoped（只管下一块） |
|---|---|---|
| 语义 | `@at` 移笔，后续步跟着落，直到再移 | `@at` 只标注紧随的一个块，其余留在主流 |
| 「2 段话+1 图+1 标题进一个区域」（brief §1 步 1 的原话场景） | 1 个声明 | 4 个声明（逐块重复） |
| 「图在右边、左边继续推」 | 3 个声明（`@at left` 铺散文 → `@at right` 放图 → `@at left` 回来推） | 1 个声明（只标图；散文天然留在主流） |
| 与板/墙的同构性 | 完全同构（`@turn` 也是 pen-scoped 的板间移动） | 破坏同构（出现「主流」这个特权概念） |
| 恢复语义（回头续写一个区域） | 自然成立（`@at left` = 恢复游标） | 需要额外机制 |
| 裁决 | **产品负责人随 ① 认可**（2026-08-11） | 记录在案防重议 |

### 3.5 与既有动词的重塑（全部带日期理由改写，台账 §12.4）

- **`@erase` 粒度收窄到区域/置放。** 裸 `@erase` = 擦**笔所在区域**（长卷上 =
  笔所在**置放**；笔在 `full` 时 = 关闭 `full` 的 open run）；`@erase "锚"` =
  擦**锚所在区域/置放**。未声明板上区域 = `full` = 整板，语义与今天逐字相同
  （兼容性免费）。可行性稿 §2.3 当年自己预告过「v2 区域级擦除可在同一契约下
  加」——现在到了，且 §2.2 的不相交判据在区域粒度平凡成立（每步属于恰好一个
  run；每 run 至多被一个擦除关闭）⇒ **erase 仍是 `Revealable`，机制零改动**，
  橡皮扫过的矩形从板变成区域/置放（参数级）。整板一次擦干净的专用形式
  （如 `@erase board`）**deferred**（§16-5）。
- **`@turn` 保留，满墙裁决推翻。** 目标选择走 `cleanBoardTarget`（§7.3，
  三级策略的前两级）；**满墙时惰性 + 响亮 finding**（§5.5）。
  §7.6-Q1「满墙 @turn 刻意触发擦除」于 2026-08-11 推翻：当年的论据是
  「表达不应比漂移待遇更差」，而漂移（写到溢出）今天也不再擦板——
  两条路一起改，论据自洽地翻转。到达后笔站在目标板的 `full` 区域。
  长卷上 `@turn` 仍是 BadStep（没有下一块板，既有裁决不变）。
- **`@focus` / `@overview` / 回头标注 / `@wait` / `@board` 零变化。**

### 3.6 长卷上的置放（rev 2 重写——原「`@at` 是 BadStep」整节作废）

长卷画布化后，长卷的置放规则钉死如下：

- **合法词：`full` / `left` / `right`。** 词给 x 与宽度（§3.2 同一分数）；
  **y 锚在书写前沿**——bare `@at left|right` 开一个新置放，frame.top =
  该刻的 front（折叠从实测高度算出，确定性、前缀稳定：后来的 append 绝不
  移动它）。置放的 frame.h = ∞（长卷纵向永不 burst——它跟长卷一起向下长；
  横向溢出照报）。
- **置放是 episodic 的**：长卷上每个 bare `@at` 都开**新**置放（讲到后面
  「右边再放一张图」= 前沿处又一个短盒子，不是回到几百 px 之上的旧栏续写）。
  **恢复只走锚定形**：`@at right "旧内容"` = 回到持有该内容的置放续写
  （「先留一块空讲到了再回来填」的长卷腿）；并栏对照也走它
  （`@at left` 铺 A → `@at right "A 的开头"` 让 B 与 A 顶对齐）。
- **纵向分数词（`top`/`bottom`/四角）判 BadStep，理由必须留档**（这是
  「特例必须存活」的那个理由）：它们命名**有界面**的分数；长卷的高度无下界，
  任何有界替身要么取自视口（**R8 违规**——resize 改写 canonical）、要么是
  一个隐藏的页高常数（**分页从后门溜回来**，恰是本转向要杀死的东西）。
  消息教出路：
  `"the strip has no bottom — its face grows with the talk; use left / right, anchor with a quote, or stand boards with @board 2–4."`
- 除此之外**零特例**：同一折叠、同一盒子、同一碰撞谓词、同一预览、同一擦除。
  count=1 在折叠里只是 `H = ∞`（纵向 burst 谓词永假、走位无处可去也无需去）。

## §4 尺寸硬、后果软（D-2）

- **声明即是框（budget）**：内容以框的宽度渲染（换行、chart/graph 缩放都在
  框宽下发生），框的高度是**预算不是墙**——内容站得比框高就**下溢（burst）**，
  照常渲染（永不裁切、永不缩字、永不搬去别的板），由自检如实回报。
- **burst 的判定（rev 2，盒子术语，钉死到可测）**：
  - 具名区域（有界板）：该区域末盒 bottom > frame.bottom；
  - `full`（有界板）：末盒 bottom > H（越过板底边）；
  - 长卷：纵向永不 burst（H = ∞）；
  - 横向溢出（不可断行的宽公式等）：单独的 axis note 进同一 finding，
    **不进碰撞几何**（v1 碰撞矩形横向一律取盒宽）。
- **具名区域永不走位**（`full` 除外——它保有房间的流物理，分界线见 §7.2）：
  框满了绝不流去下一块板——走位是房间替你选位置，是被删掉的物理。
  修复动作全部归 agent：拆步、换更大的词、擦一块、重写尾巴。

## §5 碰撞（D-3）——精确到可测（rev 2：谓词落在盒子上）

### 5.1 站立占用（standing boxes）

一个区域/置放在 cut 处的**声称占用** = 其 open run 的**站立盒子矩形集合**
（盒 x/y/w 出自折叠，h 实测；已擦 run 的盒子不站立、不参与）。
**命名是诚实的一部分：盒子矩形是"声称"，不是"墨迹"**——`full` 的散文盒
声称整个板宽，右侧可能视觉上是空白。v1 刻意用盒矩形（保守 over-claim、
便宜、确定性好）；**墨迹级 extent（逐行实测 ink 宽度）列为 v2 精化**，
立项证据 = claim 碰撞的误报在实践中真实困扰过一次。

### 5.2 碰撞谓词

```
collide(a, b) ⇔ overlapW(a,b) > EPS ∧ overlapH(a,b) > EPS,  EPS = 2 board px
```

- 判定对象：**同板、不同区域/置放**的站立盒两两相交；候选框对站立盒的相交
  用同一谓词（`frame-board` 的报告，§6）；
- （rev 2）谓词落在**盒**上而非「区域跨度矩形」上——front 规则下 `full` 的
  盒子可散布在具名置放上下，跨度矩形会把中间的置放整个罩进去，制造永久
  假碰撞；盒对盒没有这个病；
- 词表矩形之间有 gutter 相隔，相邻词的框永不因舍入误撞（EPS 是第二道保险）；
- 纯矩形函数、合成输入可测（§14），实现放 `engine/regions.ts`（§7.4）。

### 5.3 碰撞是事实,不是禁令

房间**不阻止**碰撞发生：声明照常落、内容照常画（后写的墨迹叠在先写的上面,
两笔都站着、scrub 都重现——墨迹是物质,叠加不是销毁）。碰撞的全部处置是
**被看见**：预览画出来（§6）、板面本来就画着、自检报出来（§5.4）、
主动通知推一条（§5.5）。agent 的出路永远是表达：`@erase "锚"` 擦掉一方,
或在水位线上重写、换个词。

### 5.4 自检 finding（`check-board`，两个新 code）

- **`regionCollision`**（warning）：点名两造（区域词/置放 + 各自 section/step
  范围）、重叠占候选/较小一方框面积的百分比；**claim-vs-ink 的诚实措辞钉死**：
  `"…overlaps the flow's CLAIMED width — its ink may stop short; judge by frame-board or capture."`
  出路三选一写进消息：擦一方 / 未演出的一方重写换词 / 有意叠写则无视。
- **`regionBurst`**（warning）：内容比框高（或越过板底边），报超出量
  （px + 框高的百分比）与该区域站立步范围。横向溢出并入本条的 axis note。
- 孤儿家族、`refUnresolved`、既有 code 原样。`boardOverflow`（巨型单步）保留。

### 5.5 主动通知（`ViewerNotification`）

- **`boardCollision`**：rebuild 后 transition 检测新出现的碰撞对，去重键
  `collision|${panel}|${regionA}|${regionB}`（区域对字典序），同批聚合一条,
  `severity: "warning"`，`replaces: ["boardCollision"]`，消息以
  `"Look (frame-board / glance-board) before your next append."` 收尾。
- **`boardAutoErased` 死亡**（无 auto-erase 即无此事件）。
- `@turn` 满墙的惰性走 finding（`turnOnFullWall`，warning：
  `"the wall is full — every board holds standing ink; say your own retirement (@erase \"锚\") before turning."`），
  不发通知（它是讲稿里的一行,作者当场看得见 badge）。

## §6 预览：`frame-board`（贴图，不是渲染；名字已裁定）

### 6.1 它画什么（全部是事实）

输入候选声明（≤ 8 条,方言词汇原文——**动作入参词表 = 方言词表,一套词两张嘴**）：

```ts
{ placements: [{ at: string; anchor?: string; label?: string }] }
```

viewer 做四件事，全部零预测：

1. 用**与折叠同一个导出解析器**（§7.4，`resolveRegionRect` + front 规则——
   绝不抄第二份）把每条声明解析成矩形；解析失败（词不在该面的表 / 锚不中）
   逐条如实回报；
2. 在 panels 元素内挂一层临时 overlay（`data-bansho-frames`）：**站立盒**
   一种色相（描出现状声称的占用）、**候选框**另一种色相（半透明填充 ~18% +
   虚线边 + label 角签，A/B/C 逐条配色）、候选∩站立的**相交区打斜线**——
   三者全是已知矩形,没有一笔是预测；
3. 元素级截图（对 panels 元素成像,布局尺寸、与镜头无关——**用户的镜头
   一根手指都不碰**），走 `useCaptureAction` 同款的 PNG 落盘管道,
   把文件路径交还 agent；截完即卸 overlay（瞬态；「给人看的持久意图幽灵」
   列 v2 候选,§16-8）。（rev 2）**长卷裁窗钉死**：长卷可能数千 px 高,
   图像覆盖「候选框 ∪ 书写前沿」的包围盒外扩一档、上限两个视口高,
   报告首行如实说明所示范围（`"showing the strip from …"`）；
4. 文本报告（`message`,措辞钉死进测试）：逐条候选的解析结果（词 + 板/前沿 +
   自由/压住谁 + 重叠百分比,用 §5.2 同一谓词）+ 诚实基线行。

### 6.2 两个「现在」——文本答文档末尾,图像答播放头

reveal 是**涂装级**的（wipe/fade/stroke 都不占布局变化,内容 mount 即占位）,
所以**布局几何在任何时刻都是文档末尾的真相**——碰撞报告（矩形算术）永远精确。
截图显示的是**用户此刻看到的涂装**（播放头真相）。两者的落差用基线行如实说：

```
The image shows the wall as the user sees it now (played through §2 step 5;
3 steps still to perform). Frames are declarations, not predictions —
whether content FILLS its frame is answered after you write, by glance and capture.
```

### 6.3 它绝不画什么（诚实的定义,负向测试钉住）

不画候选内容的任何模拟（无假文字、无预测高度、无预测换行）· 不画
「折叠会把它放哪」的推演（画布模型里没有这种推演）· 不建议位置（房间不再选位,
预览是镜子不是导购）· 不为避撞挪动或缩小候选框（画的必须恰是声明的）·
不画「会被擦掉什么」（没有会被擦掉的东西）。

### 6.4 一个动作还是三个——三个器官,一套神经

| 器官 | 回答 | 时刻 | 成本 |
|---|---|---|---|
| `glance-board`（感知） | 现在**是**什么样 | 每个 append 批次前;中段修改后 | 极低（文本） |
| **`frame-board`（构想）** | 我的**声明**摆上去什么样 | 循环第 3 步——想象占位区域时;碰撞警告后重规划时 | 中（一张图） |
| `check-board`（诊断） | 有什么**不对** | 一批编辑落盘后;收到警告后 | 低 |

不并入 `glance`（成本档与节奏时刻都不同：glance 每批都调,frame 在构图时调）;
不并入 `capture`（capture 答「实际长什么样」,入参是地址;frame 答「声明盖住什么」,
入参是候选;capture 保持通用）。空候选的 `frame-board {}` = 只画站立盒的
注解截图（「看清版面结构」,同一条绘制路径,近零边际成本）。

## §7 重建的折叠（`engine/layout.ts`）

### 7.1 归属折叠的推广（保住三条挣来的性质）

- **输出形状**（在既有字段上演进,mode 内部契约）：
  `assignments: Map<stepKey, { panel, region, run }>` ·
  （rev 2）**`boxes: Map<stepKey, { x, y, w }>`**——每个占空间步的盒原点与宽
  （h 由实测持有,不进折叠输出）· `regions: Map<regionKey, { panel, name,
  frameTop, opened, standingRun, startSeq }>`（长卷置放的 key 带序号,
  `"panel:right#2"`）· `runs` · `eraseOps`（+ `region` 字段）·
  `orphaned` / `overflowing` 原样 · `pen: { panel, region }` · `turns` 原样 ·
  **删除 `autoEraseBefore`**。
- **确定性**：纯函数,同输入（含实测高度与边距）同输出（照旧）。
- **前缀稳定**：append 落在尾部;区域恢复 = 游标续写;front 只增不回
  （除擦除——擦除是显式表达）;任何 append 绝不移动已放置的盒（`@at` 只动笔,
  property 测试把 `@at`、front、长卷置放全部纳入生成器）。
  中途增删 `@at` 平移下游归属与**宽度**（区域变 ⇒ 换行变 ⇒ 重测量）——
  R4 家族,同类同治。
- **编译期不相交 ⇒ erase 仍是 `Revealable`**：每个内容步属于恰好一个
  (板, 区域) run;每 run 至多被一个擦除关闭;关闭时成员冻结——§2.2 判据在
  区域粒度逐字成立,`makeSeek`/回放/擦除样式通道独占全部原样。

### 7.2 物理跟着词走：`full` 是房间的流,具名区域是作者的框

- **分界线是区域词,不是进入方式**（`@at full` 与缺省的 `full` 同一物理）：
  - **具名区域（8 词/长卷 2 词）**：x/w/frameTop 来自词 +（长卷）声明刻的
    front;游标私有;满了 burst,**永不走位**。有界板上具名归属零测量
    （parse 即知板与词）;长卷置放的 frameTop 依赖前缀实测高度——
    确定性与前缀稳定不受影响（front 是折叠自己的量）。
  - **`full`**：盒子落在板的 front（§2.2）;有界板上放不下时走
    `cleanBoardTarget`（fresh → wiped;null ⇒ 原地 burst）;长卷 H=∞ 永不走。
- **build 顺序 pin（rev 2 简化）**：总画布下**所有**盒子由折叠定位,
  provisional-then-distribute 的双路径死亡——build 一律:parse → 具名步按
  区域宽、`full` 步按板宽 mount 进 measure 流程 → 实测 h 与边距 → 折叠算
  (x, y) → 盒子落位。实现者不得让任何步先以错误宽度测量（具名步的测量容器
  宽必须 = 词宽,§9 的守卫）。

### 7.3 房间策略函数收缩:`nextOverflowTarget` → `cleanBoardTarget`

```ts
cleanBoardTarget(panelStates): { panel; kind: "fresh" | "wiped" } | null
```

三级变两级,第三级（auto-erase）删除,**null = 满墙,房间无话可说**。
三个消费者不变式照旧一份实现:`full` 链溢出走位（null ⇒ 原地 burst,不走）、
`@turn` 目标（null ⇒ 惰性 + `turnOnFullWall`,**不得**在惰性分支调用后再决策）、
glance 的 `pen.next`（null ⇒ "full wall" 形态;长卷恒 null 且渲染省略,
旧设计同款）。

### 7.4 新文件 `engine/regions.ts`（纯,零 DOM）

区域词表 enum（分面:有界板 9 词/长卷 3 词）+ `resolveRegionRect(name, W, H)`
（§3.2 表的唯一实现;长卷传 `H = Infinity`,纵向分数词返回类别错误）+
`collide(a, b)`（§5.2）+ `detectCollisions(boxes)`。折叠、`frame-board`、
`check-board` 三个消费者同一份——第二份抄写即漂移,§4.1（snapshot design）
禁令原样适用。

### 7.5（rev 2 新增）盒间距模型——y 的算术,钉死到可复核

盒 y 不再来自 CSS flow,来自折叠:

```
y(首盒 of full-run/置放) = front 或 frameTop + 区域游标
y(后继盒)             = y(前盒) + h(前盒) + gap(前盒, 后盒)
gap(a, b)             = max(marginBottom(a), marginTop(b))   // 边距折叠的显式化
```

- `h`/`margin*` 都是实测值（今天 `foldHeight` 已连边距一起量——同一来源,
  拆开记录）;**gap 公式是 CSS 相邻边距折叠的显式复刻**,意图是与现行视觉
  间距不可分辨,但**不承诺逐字节相等**（baseline 对齐、百分比边距等边角
  可产生 px 级差）——差异由 §12.2 的重奠基协议逐步核算,不许静默。
- 这个模型是 §12.2 y-oracle 的依据:同一公式喂**旧采集**的 h 与边距,
  必须得出新采集的 y——oracle 的输入来自旧代码的现实,非循环。

## §8 viewer 结构（rev 2 重写——盒子挂载）

- **每个占空间步一个绝对定位盒**（`data-bansho-ref` 原样,盒即步元素的
  定位包装）:x/y/w 来自折叠,盒内普通文档流。区域不再需要 DOM 容器——
  区域只活在折叠的几何里;closed run 的隐藏、reconcile、erase 揭示按盒
  （步 key → 盒元素,机制原样）。
- **（rev 2.1)板高必须显式落回元素**:绝对定位的孩子撑不起父元素——
  长卷元素的高度改由 viewer 从折叠读出并写死（`max(盒 bottom) + padding`;
  有界板照旧 `panelHeightFor`）。镜头算术与 `@overview` 读的是
  `offsetHeight`（G8-J 的 layout 列),这一行不写,跟随与拟合双双失真。
- **测量宽度 = 词宽**:measure host 按盒的区域宽测;`foldHeight` 缓存照旧
  按 item 存,增记 marginTop/Bottom（§7.5 的输入;一个步的宽度不经文档编辑
  不变,缓存键无需带宽）。
- **墨迹 overlay 挂进盒**（不再挂板根）:块内几何照旧按实测文字位置,
  坐标基换成盒。**这条是书写仿真的地基**（§13）:将来每盒的歪斜/漂移加在
  盒 transform 上,盒内墨迹免费同基变换——「短文本框的不规则感」的质感半
  在结构上已就位。跨盒的回头标注挂**目标步的盒**（锚随目标住,与「锚随目标
  擦」同一归属逻辑）。
- **镜头零机制变化**:笔矩形 = 笔的下一落点（front 或区域游标,折叠即知）;
  `@overview` 拟合站立盒并集;`@focus`/follow/衰减全部原样。长卷跟随 =
  今天的向下推进。
- **笔记视图原样且升格为控制组**:遍历内容步、忽略舞台步与 `@at`、单列
  CSS flow 线性化（笔记的宽度自取)——它**刻意不搬盒模型**（笔记是文档投影,
  不是画布投影）,因此成为 §12.2 里「工厂/墨迹/测量未被动过」的逐字节对照仪。
- **播放/scrub 原样**:`@at` 无 revealable,窗口占位走 dispatch-nowhere;
  擦除回放既有三层场景在区域粒度重验（§14）。

## §9 「块内仍是流式」的检验（brief §4 是我提的,现在测它——它是迁移估算的承重墙）

**结论（rev 2 收窄后仍成立）:流式活在盒内;盒间是折叠算术。**

- **盒内**:区域 = 窄一点的板。板宽从来是测量的输入（换行、chart 缩放、
  对齐列宽都是「给定宽度下的实测」）,把 W 换成词宽不碰任何机制——
  chart/graph factory 本来就按容器 `clientWidth` 画,KaTeX 块在容器内居中。
  墨迹按实测文字位置量,基换盒（§8）,**盒内几何逐字节不变**——这正是
  §12.2 用「盒相对墨迹字节不变」做重奠基证据的前提。
- **（rev 2.1 已实证,不再是推断)对齐组跨盒存活**:并列对齐的列宽机制是
  **每个条目自带一个 `bansho-align-spacer`**,宽度经 `MeasureContext.alignShift`
  由宿主按组算好逐条喂入（`engine/factories/prose.ts:149–157`)——
  它从不依赖条目共居一个 flow 容器,所以「每步一盒」不碰它;
  组的成员声明进不同区域时组自然断开（既有「无分隔符即断组」语义的空间版)。
- **盒间（rev 2 的新边界）**:y 来自 §7.5 的显式模型,不再来自 CSS。
  代价与收益都要如实记:代价是与 CSS flow 的 px 级差异要逐板核算（§12.2）;
  收益是「贴内容块」成为字面事实——没有盒子,长卷的不规则感、每盒变形、
  声明式落位三者都无从谈起。
- **必须钉死的守卫**:具名步的测量容器宽 = 词宽（负向测试断言）;
  新 factory 几何只来自挂载容器（可加 G8-J 式扫描,deferred）。
- 若实现中出现「必须给 agent 暴露换行/行高才能工作」的场景,**按本节承诺
  响亮上报**,迁移估算作废重议——不许悄悄绕。

### 12.2 重奠基协议（rev 2——替代逐字节门的证据,逐条说清各证明什么）

逐字节退化门的前提（「未声明板不许动」)被产品裁决取消;替代不是一个更弱的门,
是**换了问题的门**——从「有没有东西动了」变成「**动的是不是恰好、且仅是、
模型说要动的**」（layout-baseline README 末节的既有姿态,公式墨迹先例)。
本次比公式先例难在**没有不受影响的对照板**——对照从「第三块板」换成
「第二个投影 + 派生 oracle」:

1. **笔记投影逐字节门（幸存的真字节门,新的控制组)**:笔记视图刻意不搬
   盒模型（§8)——同会话 A/B 笔记投影零 diff,机械证明 parser、六 factory、
   盒内墨迹、测量管线全部未被动过。探针为笔记视图加采集面。
2. **x / w / h / margin 逐步不变**:同会话 pre/post,每步盒宽、盒高、x、
   marginTop/Bottom 不变（未声明内容宽度未变 ⇒ 换行不变——re-wrap 是
   本协议的一票否决;margin 不变是 3a oracle 成立的前提)。
3. **y 的两道核算（rev 2.1 拆分——两道查的是不同的东西,不许混）**:
   - **3a 实现保真:新 y == oracle,逐字节,零容差,零归因。**
     oracle = §7.5 公式喂**旧采集**的 h 与 margin（输入来自旧代码的现实,
     非循环)。既然 2 已钉死 h/margin 不变,任何 3a 差异都**只能**是
     定位引擎的 bug——这里不存在「margin 边角」一类的解释,
     不许把引擎漂移当模型偏差挥手放行。
   - **3b 模型保真:oracle vs 旧采集的实际 CSS y。**
     margin 折叠边角、baseline 对齐效应住在**这里**——每条 delta 归因并
     记录在基线 README,喂给第 5 项的视觉复核。**未归因的差 = 回归**,
     不许加模糊系数。
4. **盒相对墨迹逐字节不变**:探针升级后 `d` 串按盒记录——盒动、墨迹随盒,
   盒内 `d` 必须逐字节等。这要求**探针升级先于盒模型落地**
   （对旧代码用新探针采基线,两侧同格式;README「诚实刷新」纪律的应用)。
5. **同会话双侧视觉复核**:三块长卷 + staged 演示板逐一截图对比归档
   （`harness/screenshots/` 惯例),差异逐条对得上 3 的归因清单。

三块长卷仪器（`fourier`/`kelly`/`brain`)与 staged 演示板全部走此协议
**有意重奠基**;刷新说明按 README 纪律写明「为什么动、动了什么」。

## §17 协调者裁决（2026-08-11，V2 开工前）

产品负责人此前授权：区域用软性大致分区、尺寸硬后果软、写满归 agent
（brief §3）。以下三条落在那个授权之内，**我裁，不再问**；余下一条见 §17.4。

### 17.1 ③ 9 词封闭集：批准，横幅/双栏缺口**接受**

`full` / `left` / `right` / `top` / `bottom` / 四角。**接受**「横幅 + 其下双栏」
在 v1 说不出来——它需要的是三分带或显式栅格，而那正是把作者拖回算术的第一步。
词表的生长规则已定：**只加词，永不加数字**；真出现第二次需求再加
（`banner` 之类），一次需求不铸词。

### 17.2 ⑤ `@erase` 收窄到区域粒度：批准

擦除的目标从「整块板」收窄到「区域 / 一次置放」。理由：置放让内容有了
比板更小的边界，而擦除的语义是「**它完成使命了**」——完成使命的单位
本来就是一段论证，不是一块板。整板专用形式 deferred（`@erase` 裸形
仍然是「笔下这块板」，够用）。

### 17.3 ⑦ SKILL.md 门 435 > 430：**提门到 450，一次**

上一次（0.5.0）已经为了塞进节奏教学裁掉过三处产品评审过的文案，我当时
明说了「不会再裁第二次」。**这次照办：提门，不裁。** 提到 450 而不是 440——
V2 之后还有书写仿真与 3D 玩法要教，440 会立刻再撞一次，而
「反复微调门值」会把门训练成噪音（这条论证在 0.5.0 提门时就写过）。

### 17.4 ④ 满墙物理：**原地 burst**（2026-08-11 我裁，产品负责人授权不等他）

产品负责人指示「不用等我把后续 v2 都做完」，所以这条我裁了：**原地 burst**。
推翻成本很低（折叠里的一个分支），若判错回头改即可。原论证保留在下面。两种读法都自洽，但它们教给作者的是**不同的世界观**：

- **原地 burst**（设计推荐）：区域满了就在原地溢出，房间不动手。
  作者看见重叠、自己决定擦谁——完全贯彻 D-3「房间永不悄悄拆板」。
- **走到最早写满的板顶叠写**（「重叠」的字面读法）：房间仍然选一块板，
  只是不擦、改为叠写。

差别在于**房间还有没有主动权**。D-3 删掉 auto-erase 的理由是「拆板不该悄悄发生」，
但它没说「房间不该再选板」——`@turn` 至今仍然让房间挑下一块。
所以两种读法都不违背已定原则，需要产品负责人的一句话。

**我的倾向：原地 burst。** 因为「走到别的板去叠写」意味着**内容会出现在
作者没有说过的地方**，那比重叠更难预料；而重叠至少发生在作者刚刚指定的那个区域里，
预览一看就见。

### 17.5 §16-6 附注：长卷纵向分数词维持 BadStep

设计在裁决框架内判「长卷上 `top`/`bottom` 一类纵向词是坏步」，理由是
无界轴上的有界词没有参照（取视口 ⇒ 窗口高度改写时间轴，破 R8；取分页 ⇒
分页从后门溜回来）。**我同意并维持。** 若将来要打通，先解「无界轴上的有界词
取何参照」，那是一个独立的设计问题，不该夹在 V2 里。

### 17.6 V2 阶段 1–2 的四条裁量（2026-08-11，我裁）

实现者按 V1 立下的规矩把裁量摆出来而不是吞掉，逐条裁：

1. **`@at` 对镜头完全惰性 —— 批准。** 设计 §3.1 说镜头分类「照抄 erase/turn」，
   但 `turn` 在寄存器沉默时**是会走位的**。实现者给 `at` 不带任何 rect，理由：
   转板改变的是笔面对哪块板（否则下一次移动会从陈旧姿态出发），
   而置放**横跨的是镜头已经在看的那一面**，随后的书写会通过普通跟随把视线带过去。
   给它一个目的地，等于在什么都没写的时刻让画面猛地一跳。**判得对。**
2. **`engine/types.ts` 获得它的第一个 import（type-only，指向 `regions.ts`）—— 批准。**
   于是 `AtStep.region` **就是**那张封闭词表，而不是一份会漂移的复述联合类型。
   它同时改写了文件头「ZERO imports」的分层声明——**改得对：文档要说真话**，
   而这个 import 是 type-only、零运行时代价。
3. **不认识的区域词判 BadStep，绝不回退到 `full` —— 批准。**
   静默默认会把内容放到作者从没说过的地方，那正是这次转向要删掉的失败模式。
4. **`place` 时长初值取 `turn` 的 0.84 —— 批准。** 走到右栏和走到下一块板
   是同一个手势的不同尺度，目前没有证据把它们分开。终值归 T5。

**另记一条它自己抓到的坑（值得所有人记住）：** 它一度把 `KNOWN_DIRECTIVE`
多加了一个词（`turn`），而那个正则喂 `isBlockStart`——于是**改变了一个既有动词
与段落合并的交互**。1092 个测试全绿，因为**没有任何 fixture 会把指令紧贴在
句子下面不空行**。它自己发现并回退。教训：**全绿不等于安全，尤其当改动落在
"解析什么算一个块"这种所有内容都流经的窄口上。**

`@turn` 确实不在 `KNOWN_DIRECTIVE` 里（`erase`/`board`/`focus`/`overview` 都在），
这是真实的潜在不一致；实现者判「需要自己的改动和自己的证据」——**同意，已另开任务**，
不夹在 V2 里。
