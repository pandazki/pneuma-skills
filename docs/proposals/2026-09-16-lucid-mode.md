# Mode design brief — Lucid

Status: draft for user confirmation (2026-09-16). Produced by the `create-mode`
journey from repository evidence plus two upstream studies:

- **achimala/dream-loop** (MIT, commit `9bddb90`) — the skill this mode ports.
- **alchaincyf/3d-vibe-coding-handbook** (CC BY-NC-SA 4.0, v260914c) — measured
  practice for Tripo/AI-generated GLBs in Three.js and Blender. Its license is
  incompatible with this MIT repository, so nothing from it is copied; its
  *findings* inform our own scripts and skill text and are cited as such.

## Identity

- name: `lucid` (the upstream skill is credited through `inspiredBy`; the user asked for a name of our own)
- displayName: `Lucid` / `清明梦` / `ルシッド`
- description: Dream a target screenshot with image generation, build a Three.js
  scene toward it, and let a fresh-context judge score every round until the
  live frame matches the dream.
- icon: lucide-style single path — a circular arrow with a small square viewfinder
  inside (the loop around a frame).
- installName: `pneuma-lucid`
- inspiredBy: `{ name: "achimala/dream-loop", url: "https://github.com/achimala/dream-loop" }`
- supportedBackends: `["codex"]` (see External integrations)

## Domain

The user wants an unusually good-looking 3D scene, game or app in the browser.
The mode turns that into a closed loop with four objects: the **target** (a
"dream" screenshot generated by the model's own image tool, locked at
`target.png`), the **scene** (a static Three.js site the agent builds under
`scene/`), a **round** (one live capture of the scene plus a judge verdict
scored 0–10 on composition / lighting / materials / details), and the **asset
ledger** (every model the scene needs, with where it came from: image-to-3D,
Blender, or procedural). The viewer is the loop's instrument panel: the live
scene in an iframe, the target beside or over it with a wipe slider, the score
trajectory across rounds, and the asset ledger. The agent builds, captures,
delegates judging to a fresh subagent, records the verdict through a script,
and reads the exit criteria from the same script instead of deciding them in
prose.

## Invariants and implementation choice

- **`lucid.json` and `rounds/**` are written only by `lucid.mjs`.**
  A round is a capture path + verdict + timestamp; the exit rule (score ≥ 8 and
  fps acceptable; stall when the best score has not gained a full point in two
  rounds or the judge repeats a gap) is computed by `lucid.mjs status`,
  never by the agent's memory of the history. Verified by domain tests over
  fixture histories (improving, stalled, regressed, budget exhausted).
- **The target is locked once the loop starts.** `target.png` is replaced only
  through `lucid.mjs target --set <png>`, which archives the previous
  target under `target-history/` and records the swap as a round-0 event, so a
  score trajectory never silently compares against two different dreams.
- **The scene must be self-contained static web.** Everything under `scene/`
  resolves by relative path; three.js and its addons are vendored from one
  pinned version. This is what lets `/content/<project>/scene/index.html` run
  in the viewer iframe with no dev server, and what keeps a future hosted-player
  or deploy surface possible.
- **The live frame is read through the scene's bridge, never guessed.** The
  scene includes `lucid-bridge.js` (copied by the script into `scene/`),
  which answers the viewer's `postMessage` requests: render one frame and
  return the canvas PNG, and report `{ ready, fps, frameMs, drawCalls,
  triangles, textures, errors[] }`. `capture` and `get-scene-state` go through
  it. A scene without the bridge still displays, but the viewer marks it
  "unmeasured" and the skill treats that as a blocker before judging.
- **State and writers.** Persistent: `lucid.json`, `target.png`,
  `rounds/NN/{capture.png,verdict.json}`, `assets/**`, `scene/**` (script for
  the first three, agent for the last two). Transient UI state (view mode,
  wipe position, selected round) lives in the viewer and is never persisted.
- **Reuse.** Viewer shell: webcraft's same-origin iframe over `/content/*`
  (the static-web fast path). Capture registration: sprite's
  `setStageCapture` ref pattern. fal transport: `_shared/scripts/fal-queue.mjs`
  primitives (`loadFalKey`, `falMediaUrl`, `downloadFalFile`); the resumable
  job-file semantics (`check` / `submit` / `collect`, never resubmit an
  uncertain job) are transcribed from upstream `fal-batch.mjs` (MIT, NOTICE).
  Decimation and texture resize: `@gltf-transform/cli` via `npx --yes` — the
  handbook's E0 experiment showed Blender and gltf-transform produce equivalent
  decimation (6,772 vs 6,781 faces on the same asset), so Blender is reserved
  for what only it does.
- **Added complexity.** Two framework companion changes (below) and one Python
  helper set for headless Blender. No new core contract.

## Source layer

- kind: `aggregate-file`
- domain type:

  ```ts
  interface Loops { projects: Record<string, Loop> }          // key = content-set dir
  interface Loop {
    dir: string; title: string; status: "dreaming" | "looping" | "done" | "stalled";
    target: { path: string | null; version: number; lockedAt?: string };
    budget?: { minutes: number; startedAt: string };
    fpsTarget: number;
    rounds: Round[];                                          // ordered by index
    assets: AssetEntry[];
    warnings: string[];                                       // e.g. scene missing bridge
  }
  interface Round { index: number; capture: string | null; verdict: Verdict | null; at: string; fps?: number }
  interface Verdict { composition: number; lighting: number; materials: number; details: number; total: number; gaps: Gap[]; summary?: string }
  interface Gap { area: "composition" | "lighting" | "materials" | "details"; issue: string; fix: string }
  interface AssetEntry { id: string; role: "hero" | "prop" | "environment"; source: "image-to-3d" | "blender" | "procedural" | "user"; state: string; files: string[] }
  ```

- why this kind: the loop is one object assembled from a manifest plus N
  per-round JSON files and PNGs; removing a verdict file breaks the trajectory,
  so it is an aggregate, not a list of independent files. Sprite's
  `Roster`/`project.json` is the precedent.
- patterns: `**/lucid.json`, `**/rounds/**/verdict.json`, plus PNG presence
  through the file list. All text files are `.json`, inside the player's
  `TEXT_EXTENSIONS` allowlist.
- domain.ts needed: yes (`loadLoops`, `saveLoops` — save is a pure identity
  writer for the manifest; the viewer never writes rounds).

## Workspace model

- type: `"manifest"`, manifestFile: `lucid.json`
- multiFile: true, ordered: true (rounds), hasActiveFile: false
- supportsContentSets: true — one project per top-level directory, like sprite
- topBarNavigation: false — the rounds rail lives in the viewer

## ViewerAddress vocabulary

| Key | Kind | Meaning |
|---|---|---|
| `contentSet` | framework-reserved | Project directory (`"lantern-shrine"`) |
| `round` | coarse | 0-based round index; navigating shows that round's capture against the target |
| `view` | fine | `"live"` (scene iframe), `"target"`, or `"split"` (wipe compare); in-place switch |

Example: `{ "contentSet": "lantern-shrine", "round": 3, "view": "split" }`.
`round` is registered in `COARSE_ADDRESS_KEYS` (`src/hooks/useCaptureAction.ts`)
so `capture` navigates before it shoots; a capture with no `round` shoots the
live scene through the bridge.

## Action space

| id | label | category | agentInvocable | params |
|----|-------|----------|----------------|--------|
| navigate-to | Show round / view | navigate | true | `{ address: object }` |
| get-scene-state | Read what the scene reports | custom | true | `{}` → `{ ready, fps, frameMs, drawCalls, triangles, textures, errors[], bridge: boolean, viewport }` |
| reload-scene | Reload the live scene | ui | true | `{}` — after a batch of edits, so the agent controls when the iframe restarts (viewer also auto-reloads, debounced 1.5 s after the last file change) |

`capture` is framework-built-in; for this mode it is served by the mode's
`captureViewport` (bridge PNG), see companion change 2.

Commands (user → agent, one-line hover hints only):

| id | label | hint |
|----|-------|------|
| judge-round | Judge this round | Capture the scene now and ask a fresh judge to score it against the target |
| re-dream | Dream a better target | Generate a new target from the current scene's screenshot and the original direction |

## Scripts (mode-owned, `skill/scripts/`)

| Script | Subcommands | Owns |
|---|---|---|
| `lucid.mjs` | `init`, `target --set`, `round add --capture`, `verdict --round N --file`, `status`, `budget`, `asset add/update` | `lucid.json`, `rounds/**`, `target-history/`; exit-criteria evaluation; copies `lucid-bridge.js` into `scene/` on `init` |
| `image-to-3d.mjs` | `check`, `submit`, `collect` over `assets/fal-jobs.json` | Tripo H3.1 (`tripo3d/h3.1/image-to-3d`) and Trellis (`fal-ai/trellis`) recipes; resumable job file; downloads validated GLB 2.0 |
| `blender.mjs` | `doctor`, `run <script.py> -- …`, `render-views <glb> <out.png>`, `convert <fbx> <glb>` | Locates the binary (`BLENDER_PATH` → `{{blenderPath}}` → PATH → `/Applications/Blender.app/…` → Program Files → `/usr/bin/blender`), runs `--background --factory-startup --python`, prints every step, verifies outputs by size not exit code |
| `glb.mjs` | `inspect`, `resize`, `simplify`, `optimize`, `normalize-report` | Pure-JS GLB header/JSON reading (tris, verts, textures + sizes, bbox, `doubleSided`, `extensionsRequired`, normalized accessors); gltf-transform wrappers with per-role ratio defaults (people/vehicles/props aggressive, buildings conservative, trees/lattices barely) |

Python helpers under `skill/scripts/blender/` are original: `render_views.py`
(six views in glTF axis convention: −Z, +X, +Z, −X, top, iso — because four
views cannot tell front from back), `fbx_to_glb.py` (with backface-culling
fixed so `doubleSided` is not silently true), `probe.py` (scene stats after
import, skipping `glTF_not_exported`).

## Viewer

`DreamLoopPreview` (editor layout):

- **Stage**: same-origin iframe at `/content/<project>/scene/index.html`, with
  Live / Target / Split segmented control (custom, token-styled; no native
  controls). Split renders the target as an overlay clipped by a draggable
  wipe. Target view shows `target.png` at the stage's aspect.
- **Rounds rail** (bottom): one chip per round with score, a sparkline of the
  trajectory, the best round highlighted; click selects the round (capture vs
  target in Split), which becomes the selection's address.
- **Status strip**: fps / frameMs / triangles / textures from the bridge, budget
  remaining, `status` verdict (looping / stall approaching / done), and
  warnings (no bridge, scene errors).
- **Asset ledger** (collapsible side sheet): assets with source and state.
- Read-only when `editing === false`: commands hidden, everything else renders.

## Seed strategy

- shape: single project content set (`lantern-shrine/`)
- narrative: "an isometric shrine courtyard at dusk, lanterns on wet stone",
  one locked target, a small vendored-three scene with one Blender-made GLB and
  procedural ground, two recorded rounds (about 4.5 then 6.8) with verdict JSON
  naming real gaps — the user opens the mode already inside a loop.
- production: the target PNG and the two captures are produced by a real
  codex + GPT-6 Astra session (the blind trial below), not hand-drawn.
- vendored three: five files (`three.module.js`, `GLTFLoader`, `OrbitControls`,
  `BufferGeometryUtils`, `SkeletonUtils`) from one pinned npm version; package
  size checked before release.

## External integrations

- **Backend lock**: `supportedBackends: ["codex"]`. The dream and every asset
  cut-out / texture come from the model's built-in image generation; codex
  0.154 exposes it (`image_generation` feature, stable) and Pneuma already
  launches codex with `--enable multi_agent`, which supplies the fresh-context
  judge. The manifest cannot pin a model; the skill's first step checks for an
  image tool and stops with a clear message if the session's model has none.
- **init.params**:
  - `blenderPath` (string, default "" = auto-detect) → env `BLENDER_PATH`
  - `falApiKey` (string, sensitive, optional) → env `FAL_KEY`; `deriveParams`
    sets `imageTo3dEnabled`
  - `fpsTarget` (select: 60 / 30) → default for `lucid.mjs init`
- **proxy**: none. **skill.mcpServers**: none — Blender is driven headless by
  script, which is portable across harnesses and needs no MCP server.
- **sharedScripts**: `fal-queue.mjs` (transport primitives for image-to-3d).
- **refreshStrategy**: `"auto"` with a viewer-side 1.5 s debounce on iframe reload.
- **NOTICE.md required: yes** — upstream achimala/dream-loop (MIT, `9bddb90`):
  the judge rubric prompt, the exit criteria, the "target is an in-engine
  screenshot, not concept art" guidance, the asset-sourcing ladder, and the
  fal job-file semantics.
- **External effects**: fal submissions are paid and have no idempotency key;
  `submit` records `submitting` before the POST and never resubmits a record
  that is `submission-uncertain`; `collect` is one pass, re-run by the agent;
  cancellation is not attempted (jobs are minutes long and cheap to let finish).
  Blender runs are local and re-runnable; outputs are written atomically.

## Companion framework changes (outside `modes/`)

1. **`backends/codex/codex-adapter.ts`** — surface `imageGeneration` items as a
   `tool_use` (`ImageGeneration`, input `{ revisedPrompt?, transparentBackground? }`)
   on `item/started` and a `tool_result` carrying `savedPath` (or the
   `usageLimitExceeded` failure) on `item/completed`; likewise `imageView` →
   `ImageView { path }`. Today both fall into the `default:` branch and vanish
   from the chat, so the user would watch the agent "think" while the dream is
   being drawn. Tests mirror the existing webSearch cases; README item table
   updated.
2. **`src/utils/viewer-capture.ts`** — for a full capture, try the mode's
   `captureViewport` before the snapdom-on-iframe path when the mode provides
   one. A WebGL canvas inside a same-origin iframe snapshots black under
   snapdom; the mode's renderer knows how to draw a real frame. Thumbnail
   capture already uses this order. Plus the `round` entry in
   `COARSE_ADDRESS_KEYS` with the pinned test extended.

## Cloud surfaces

- hosted player: **no** for 0.1 — the viewer is built on the static-web fast
  path (iframe over `/content/*`, JSON sources), so it can earn the whitelist
  later, but the obligation (player build + real package + browser pass with a
  WebGL scene streaming GLBs through the content service worker) is deferred
  until the viewer settles.
- artifact deploy: **none** for 0.1 — the scene is a static site and an
  `/export/lucid` route with `collectDeployFiles()` over `scene/` is an
  obvious follow-up.

## Launcher surface

- visibility: public
- featured-eligible: yes

## Evolution directive

> Learn the user's visual taste and loop habits: the art directions and camera
> framings they ask for, how they phrase target-image prompts, how strict they
> want the judge, which asset rungs they prefer (image-to-3D vs Blender vs
> procedural) and their usual fps target and time budget. Evidence comes from
> session history, `lucid.json` histories and verdicts. Write them back as
> this skill's defaults so a new loop starts from the user's house style while
> explicit instructions still win.

## Verification plan

1. Unit: domain load/save, `status` exit rules, `glb.mjs inspect` on fixtures,
   `image-to-3d.mjs` with a mocked fetch (resume, no double spend), `blender.mjs`
   detection order with a fake binary, adapter tests for `imageGeneration`,
   capture precedence test.
2. Visual: own `--viewing` session, screenshots of Live / Target / Split, rounds
   rail, status strip, empty state.
3. **Blind trial (isolated port + browser)**: a cold-start codex + GPT-6 Astra
   session runs the upstream README prompt with a 45-minute budget; we keep the
   resulting target, rounds and scene as the seed, and record what the agent
   improvised outside the scripts as skill fixes. Blender path exercised once by
   having the agent model one prop headless.
