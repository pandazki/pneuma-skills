## §G 增补（随 C3 落地）

### G5 重写（替换 tasks §G5 全文）

> **板面可擦，历史不可擦。** 擦除是显式的、串行的表达动作，**只能以追加擦除指令的方式
> 发生**；它改变板面此刻的呈现，不改变 canonical timeline，也不触碰讲稿文件。
> scrub 回拖到擦除之前，被擦内容**必须重现**。课堂笔记遍历全部内容步、忽略擦除步，
> 永远大而全。任何**隐式**的内容丢失仍然违规——分页、滚动替换、被动覆盖，
> 以及**从 `board.md` 删除已播文本**（那是删历史，不是擦板）。

原 G5 的「不要假设永不擦」写于擦除还没设计的时候，本期它兑现了，所以整条替换而不是追加。

### G8-L. 擦除必须独占一条视觉通道（新增硬规则）

目标**集合**不相交只保证了 erase 单元彼此不打架，**还必须保证 erase 的样式通道与
所有揭示策略的通道不相交**。

反例（rev 2 §2.2 推演，会真的发生）：fade 策略驱动 `opacity`。若 erase 也用 `opacity`
隐藏——C 步在 t=10..12 fade 揭示中，E 在 t=50 擦掉它，用户从 t=60 回拖到 t=11。
`makeSeek` 按索引升序分发：`C.seek(0.5)` 写 `opacity: 0.5`，紧接着 `E.seek(0)`
「恢复」`opacity: 1`——**C 变成全显，而不是半透**。wipe 的 `clip-path` 同理。

**修法：erase 用专属 wrapper 元素或专属 class，`seek(0)` 只移除自己的状态，
绝不写任何策略拥有的属性。** 与 G8-D 同族的坑：只在特定组合下暴露、不报错、悄悄坏。

## C2-impl 舞台指令

**任务**：镜头动词进方言 + `stageStateAt` 折叠 + 宿主 gate。taskKind: `feature`。依赖 C1。

### 方言

| 动词 | 语义 | 形态 |
|---|---|---|
| `@overview` | 「我们退一步看整体」 | 独立成行，无参数 |
| `@focus "锚文本"` | 「我带你去看那边」 | 内容锚定，就近向上匹配，与 `@strike` 同款 |

**永不接板号、永不接坐标**（rev 2 §1.4 推论）。方言里唯一的数字空间 token 是 C3 的 `@board n`。

`@focus` 与 `@bring`（C3b）在方言里**分开**：视觉上同为相对运动，教学动作完全不同——
「带你去看」vs「我把那块搬过来跟这块并排」。这是产品要求，也是正确的词汇设计。

### 机制（rev 2 §3 已定，别重新论证）

- `CameraStep` 进 `Step` union；`UnitKind` 加 `camera`
- 镜头步**占 schedule 独占时段**（G1：五者互斥），`targets[]` 留空 →
  走 `makeSeek` 现成的 unpaired「dispatch nowhere」路径，**零改动**
- 镜头**不实现 `Revealable`**——它是共享寄存器（多步写同一个寄存器、last-wins、
  顺序相关），只能折叠。做成 Revealable 会让回拖时的窗口遍历 + last-write-wins
  把姿态停在错误位置
- 纯函数 `stageStateAt(schedule, t) → { camera, panelOffsets }` 落在 `engine/stage.ts`

**返回形状 C2 就必须含 `panelOffsets`**，哪怕 C3b 之前没有任何东西写它。
折叠契约后补重塑是破坏性变更，方言动词后补是纯加法——这是契约先行原则的本期形态。

### 镜头寄存器必须能取值「跟随」——这不是细节，是本期最容易漏掉的坑

天真的折叠语义是「取 t 之前最后一个镜头步的姿态」。它有两个直接后果，两个都是回归：

1. **一块不含任何镜头指令的板会冻在初始姿态**——C1 刚保住的笔尖跟随再也不跑，
   而「不写镜头指令的板行为不变」正是本期自己的验收门；
2. **一次 `@focus` 之后镜头永远钉在那儿**，笔继续在视野之外书写——
   这正是 `camera-latch.ts` 头部记录的那个真 bug（「看起来像 agent 停了」），
   C1 刚从结构上消灭了它，C2 不能从语义上把它请回来。

所以**折叠的值域必须比「一个姿态」宽**：

```ts
type CameraRegister = { kind: "pose"; x; y; z } | { kind: "follow" };
stageStateAt(schedule, t) → { camera: CameraRegister; panelOffsets: … }
```

`"follow"` 由宿主解析成 C1 已有的跟随路径——**导演不发话时，镜头跟着笔走**。

**衰减规则（本期必须钉死一条，建议如下）：** 一个镜头步的姿态在它自己的窗口内有效，
并延续到其后紧邻的**非书写步**（`@wait`、另一个镜头步之前的空档）；
**下一个书写步开始时，寄存器衰减回 `"follow"`。** 语义读起来正好是老师的动作——
「我带你看这儿（停住讲）……好，回来继续写」。

可以改用别的规则，但**必须在 C2 开工前定死一条并写进本文**——按本文自己的论证，
这正是「折叠返回形状后补重塑是破坏性变更」的典型场景，拖到 C3 再补就是返工。

**C2 实装钉死（含 from-pose 规则；2026-08-10 评审 P1-4 修订）：** 衰减规则采用
上文建议原案。配套钉死每个镜头步的**出发姿态**（它同时是 Van Wijk 弧长的输入，
产品可见）：寄存器仍锁存时（上一镜头步之后没有书写步），出发姿态 = 上一镜头
**目标**；寄存器已衰减时，出发姿态 = **实时跟随真正停住的位置**——
`resolveCameraOps` 用与宿主完全相同的算式（`followShift`，含死区；外加衰减
交还保留导演 y 的 hand-back）在文档序上**模拟**实时跟随对每个书写/擦除步的
落点；此前无任何内容时 = HOME。初版曾取「最后书写矩形的绝对代理姿态」
（`followProxyPose`），但实时跟随有死区（目标可见则不动）、交还保留 y，
代理与实机停点不一致，衰减后的镜头步会以一次可见跳变开场——评审 P1-4 证实后，
两套口径合一到实时算式上（跟随算式因此上提到 `engine/stage.ts`，
`viewer/camera.ts` 转口导出）。姿态链仍然只依赖文档序 + 实测矩形、与任何
时长无关，「姿态序列先全部解出、再逐段求弧长」的无环论证原样成立；
不受打扰的直播播放中，实机镜头恰好停在模拟停点上。

### 两条取值约定（顺手钉死，否则实现者要猜）

- **`@overview` 拟合的是「此刻为止」的内容范围**，不是整块板的最终范围。
  理由有两条且都硬：scrub 纯粹性（镜头是 t 的纯函数，不能偷看未来）；
  教学正确性（还没讲到的东西不该出现在总览里）。
- **`@focus` 目标 z = 1，以锚点所在步为中心。** 不放大——放大会让「带你去看」
  变成「凑近看」，那是另一个动作。

**镜头步的 `naturalDuration` 在 build 时就可算**，不存在时长↔时间轴的循环依赖：
第 i 个镜头步的起始姿态只取决于它**之前的镜头目标**，与任何时长无关，
所以姿态序列可以先全部解出来，再逐段求弧长得时长。

### 缓动：镜头的插值在折叠里，不在宿主里

产品负责人的原话是「镜头的缩放啥的，都需要 ease 让整个动画保住理解，最好不要全是
线性的，会很难受」。落法：

**`stageStateAt` 返回的是 t 时刻的已插值姿态**——找到 t 之前最后一个镜头步，
若 t 落在它的窗口内，则按该步自身进度在「上一姿态 → 目标姿态」之间插值。
宿主每帧只是查询并写 transform，自己不持有任何动画状态。这样 scrub 天然正确
（镜头是 t 的纯函数），也不需要第二套时钟。

**插值必须走 Van Wijk & Nuij (2003) 的平滑缩放-平移，不能对 camera 分量线性插值。**
根因：同时平移 + 缩放时，线性插值在感知上是错的——画面会先冲出去再拉回来。
正确解是在 (平移, log 缩放) 空间里做弧长参数化。这条不是锦上添花：
一个「拉远看全局再推近到另一处」的镜头，线性插值下必然晕。

镜头步的 `naturalDuration` 由**同一个弧长度量**给出——Van Wijk 的 cost 函数就是
感知距离本身，所以「近距离小挪一下」快、「跨板大跳」慢，自动成立，不需要手调。
常数进 `DurationConstants`（加法），归 T5 同一张终校表。

### 宿主 gate

viewer 每帧查 `stageStateAt` 并应用——**除非镜头被用户接管**（C1 的 detach 语义）。
导演镜头与用户镜头的优先级：用户滚轮 override 导演；`follow === "live"` 与显式 seek
交还给导演。这与 C1 已有的 detach/reset 语义**是同一套**，不要再发明第二套。

### 锚点解析 seam

`@focus "子串"` 要解析成「哪个 step + 它的矩形」。矩形是测量值，所以走
`MeasureContext` 的新增可选 seam（**镜像既有 `backRef` 的形状**——跨步节点操作
经宿主 seam 进入是既定模式，chart 层写 frame 节点、backref 墨迹画在他步文本上，
都是先例）。解析结果在 build 时写进 schedule 条目，**折叠因此保持纯函数**。

### 硬约束与验收

- G1：镜头步与写、划的时段两两零重叠（现有 property 测试原样覆盖）
- G6：`@focus`/`@overview` 的 srcSpan = 指令自己那一行
- **折叠确定性**：同一份 schedule + 同一个 t，`stageStateAt` 必须字节级同解
- **回拖正确性**：任意 t 序列乱序调用，姿态只取决于 t，不取决于调用历史（property 测试）
- 布局基线（C1 的 gate 1）：**不含镜头指令的板必须仍然零 diff**
- 视觉验证 G7：录一段「`@focus` → 讲 → `@overview`」，确认缓动不晕

## C3-impl 面积 + 擦除 + 笔记（**一个语义包，必须一起做**）

**任务**：`@board 2–4` + 归属折叠 + `@erase` + auto-erase + 笔记视图。taskKind: `feature`。依赖 C2。

**为什么不能拆**：面积有限 ⇔ 写满要擦 ⇔ 擦了要有地方兜底完整性。
只做面积不做擦 = 板写满就没救；只做擦不做笔记 = 内容真的丢了。三者互为因果。

### 方言

**`@board 1–4`** —— 首个内容块之前、独立成行。缺省 = 1 = 长条（= 现状）；
显式写 `@board 1` 同样合法——「单块 = 长条 = 现行线性模式」是产品负责人锚定的
一等公民形态（可行性稿 §1.1 也写的是 1–4），把它写出来是清晰的作者意图，
不是坏步。（2026-08-10 评审 P3-6：本行原标题写 `2|3|4` 与实现相悖，
修的是规格标题，实现、解析器与作者文档保持原样。）
中途出现 → BadStep。读感 = 讲稿开头的舞台说明（「（三块板）」）。

**必须在 `board.md` 内的硬理由**（rev 2 §5.1，别改判）：板数喂布局折叠 →
布局喂墨迹几何与舞台状态，全是 canonical 输入。放 viewer 设置或 sidecar 会让
同一份讲稿 canonical 不同，R8 当场破。

**`@erase`** = 擦当前书写板；**`@erase "锚文本"`** = 内容锚定到目标步所在的板，
整板擦除。**永不接板号。** 粒度 v1 = 整块板（rev 2 §2.3：区域级擦除引入自由空间
碎片管理，折叠复杂度陡增；而「精确否定一句」已经有 `@strike`，外科手术式擦掉一句
是两个语义的怪异杂交）。

### 板的几何（本期需要定，rev 2 §10 把它列为"仍开放，不 gate 方向"）

**以下是我按已定原则推出来的取值，产品负责人可以推翻，但实现者不要自行改动：**

- **板宽恒定，与配置无关**，等于今天的板宽。这让笔记态与板态共享测量，
  也让退化门（单块 = 现状）继续免费成立。
- **多块 = 定高并列同宽列**，横向排开，板间有缝。
- **板高 = 板宽 × 0.72**（真实教室推拉黑板的比例，宽大于高）。**必须是板宽的纯函数，
  不能取视口高度**——板高喂溢出折叠、溢出折叠合成 auto-erase 步、auto-erase 进
  canonical。取视口高度会让「窗口拉高一点」改写时间轴。
- **单块 = 长条，高度无界，不触发 auto-erase**（D11 锚定：单块长条 = 现行线性模式）。
  显式 `@erase` 在单块上仍可用（清场开新章）。
- 缩放下限随舞台范围算（`min(常数下限, viewW / stageW)`），否则 4 块并排时
  `@overview` 会被 C1 的常数钳位卡住看不全。

### 归属折叠（`engine/layout.ts`，纯函数）

板归属 = 对（step 实测高度序列, 板高, 擦除序列）的**纯前缀折叠**：按文档序填板，
放不下的 step **整步**换下一块（只在 step 边界断）；擦除把对应板的填充游标复位。

三条不变式，都要有测试：

1. **前缀稳定（R1 延伸）**：append 永远落在折叠尾部，已有 step 的板归属与坐标
   **绝不因追加而变**——擦除只隐藏、不移动（墨迹是物质）
2. **R4 同族**：块中途修改致高度变化 → 下游归属可能平移，与 R4 时间平移同类同治
3. **累积容器的家不迁移**：chart/graph 停在首现时分到的板，后文图层画回那块板

**边界**：单步高于一块板（巨型段落 / 超高图）→ **软放行 + `boardOverflow` 族 warning**，
不硬截断。巨型单步本身是坏讲稿，该说出来，但不该吞内容。

### 擦除的机制（rev 2 §2.2 已验证，照做）

- **erase 是 `Revealable` 揭示单元，不是共享寄存器。** 判据（值得记住的设计规则）：
  **状态所有权能否在编译期划成不相交集合。** 镜头/板位是「多步写同一个寄存器」，
  只能折叠；擦除目标可在编译期唯一分配——每个内容步至多被一个擦除步擦
  （它之后第一个覆盖其所在板的 erase）——于是每个 erase 单元独占一组互不相交的
  可见性状态，`Revealable` 分发安全。
- `seek(p)`：p=0 目标全可见、p=1 全隐、中间 = 板擦扫过的进度（单调 easing，幂等样式写）
- **`Revealable` / `BoardTimeline` / `makeSeek` 零改动承载。** 唯一新增是
  `MeasureContext` 的目标句柄 seam（镜像 `backRef`）
- **G8-L 独占通道**（见上）——这条漏掉就是静默视觉 bug
- **R4 族新规**：被擦目标步重建（hash 变）时，erase 单元持有的目标句柄失效，
  宿主须**重链**（与 chart 重建级联同类，进既有 REBUILD RULE 文档）

### auto-erase（不进 `Step` union）

它没有源文本，做成 Step 会破坏「Lecture = 讲稿的纯 parse」。

**正确位置：计划层合成单元**——`planStepUnits` 本来就合成无源构造的单元
（heading 的手绘底线、list 的弹点、aside 的边栏是先例）。auto-erase 作为
**触发溢出的那个 step 的前导单元**合成（「擦旧板，再写这步」），
**srcSpan = 该步的源区间**——G6 覆盖率保持 100%，且高亮语义正确：
此刻讲稿上正在写的那句话，就是逼出擦板的那句话。

选板策略：**擦最早写满的那块**（老师写满四块自然回头擦第一块）。
显式 `@erase` 之后的续写选板同理走折叠，不需要新规则。

### 笔记视图（「板 ≠ 笔记」的兑现）

同一份 canonical timeline，两种投影：

| | 板（播放态） | 课堂笔记（导出态） |
|---|---|---|
| 面积 | 有限、会擦、镜头引导 | 无限、什么都不丢 |
| 服务 | 讲的过程 | 事后回看 |
| 遍历 | 全部步 | 全部**内容**步，忽略 erase 与舞台步 |

**笔记态 ≈ C1 之前那块线性板**——是已有渲染路径的重新定位，不是新机制。
实现只有两件事：视图开关 + 过滤。

**切换时重建，不做双活 build**——factory 契约是 single-shot per mount generation，
双活会翻倍 DOM 与构建。

静态 HTML 导出（「大而全的网页版」）走 export routes 既有设施，**留 v1.5，不在本期**。

### 硬约束与验收

- **G5 新表述**（本文 §G）落 tasks 与设计稿
- **G8-L** 有测试，不只是注释
- **擦除回放测试**（这是本期的核心门）：rev 2 §2.2 推演的三层场景要跑通——
  「C1 写在 t=20 → E1 在 t=50 擦它 → C2 在 t=60 写在同一位置 → E2 在 t=90 擦 C2」，
  从 t=100 回拖到 t=20，板上必须**正好是 C1**。再叠一层 G8-L 的反例场景
  （fade 揭示中途被擦、回拖到揭示中途，必须是半透而不是全显）
- **归属折叠 property 测试**：前缀稳定 + 目标集不相交
- **退化门**：`@board` 缺省（单块）时，C1 的布局基线仍然零 diff
- G6 100%（含 auto-erase 的合成单元）
- G7 视觉验证：四块板写满 → auto-erase → 继续写，录下来看是不是「像老师」

## C3b-impl 搬板
