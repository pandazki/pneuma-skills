## 1. 「黑板面积配置」五条技术后果 —— 逐条判定

### 1.1 面积硬上限 ⇒ 不需要虚拟化:**成立,且擦除让它更强**

板数 ≤ 4、板面有界、写满即擦 ⇒ **任意时刻板面可见内容严格有界**——分块渲染 /
视口裁剪 / 按需卸载失去必要性,「前端渲染卡」在模型层被挡住。历史内容的 DOM
(被擦但保留,供 scrub 回放)按时间序增长,与今天线性板的包络同级,由既有防线
(~200 step 设计目标 + `check-board`)覆盖;`content-visibility` 提示保留(CSS 提示,
非虚拟化)。硬上限写进方言契约(`@board` 只接受 1–4,§5)。

### 1.2 ⇒ 不需要 LOD;rev 1 §9 决策门**已关闭**:**成立(结论不变,理由已按实测改写)**

**结论仍然成立,但当初写的理由(「最多 ~4 块并排的线性缩小,永远可读」)是错的,
2026-08-09 的 C3 验收实测就把它推翻了**:四块板拉满时缩放到 0.245,字根本读不了。

真正的理由是**总览的用途是方位,不是阅读**:`@overview` 回答「我在哪、还有什么」,
读一段字要走到那块板前面去——镜头和墙面缩略图就是干这个的。LOD 要解决的是
「拉远后还想读」,而这个需求在这个 mode 里根本不存在。

W7(2026-08-12,黑板有了自己的尺寸)让这条更清楚了一层:板宽不再跟着窗口,
所以**窗口越宽,同一面墙 fit 之后越大**——1280 的笔记本装下 2x2 的房间时墙确实小,
那是物理,不是缺陷;1990 的显示器同一面墙就大得多。以前板宽等于视口宽,
fit 的缩放恒等于「视口 ÷ 墙宽」,与显示器大小无关,再大的屏幕也读不了——
那才是当年 0.245 的结构性成因。

rev 1 §9 的问题(拉远时细节「变小但全在」还是「被摘要卡盖住」)**被模型消解而非
回避**;「摘要卡」的完整性诉求由**课堂笔记态**承接(§6)——这比 rev 1 的任何一个
候选都干净。LOD 从 roadmap 永久移除。

### 1.3 「几块板」= rev 1 的「命名区域」:**成立,且比 rev 1 更简单**

rev 1 押在 section 空间化 + per-section hint;新模型**修正**:空间单元是**板**,
内容 → 板的归属由溢出折叠自动决定(§1.4),section 回归纯叙事单位。坐标永不入方言
不仅守住,还更进一步:**连区域名 / 布局 hint 都不存在了**(rev 1 的两个方言候选
全部删除)。板内仍是文档流——测量、换行、对齐组、墨迹几何(G8-B/G)全部原样。
ViewerAddress `{section, step}` 是叙事坐标,所在板是派生量,T6 原样存活。

### 1.4 溢出自动换板,agent 不管空间:**成立——最不能破的一条,带一个方言级推论**

**机制:** 板归属 = 对(step 实测高度序列, 板高, 擦除序列)的**纯前缀折叠**:
按文档序填板,放不下的 step **整步**换下一块(只在 step 边界断);擦除把对应板的
填充游标复位。确定性与 canonical 同源(测量本来就喂 canonical)。三条不变式:

- **前缀稳定(R1 延伸):** append 永远落在折叠尾部,已有 step 的板归属与坐标
  **绝不因追加而变**——擦除只隐藏、不移动(墨迹是物质,§3);
- **R4 同族:** 块中途修改致高度变化 → 下游归属可能平移,与 R4 时间平移同类同治;
- **累积容器的家不迁移:** chart/graph 停在首现时分到的板,后文图层画回那块板。

**方言级推论:归属自动 ⇒ agent 不知道也不可知任何内容在第几块板。** 一切跨板引用
必须**锚内容、不锚板号**:回指已是这个形状,搬板是 `@bring "子串"`、擦除是
`@erase "子串"`(或裸 `@erase` = 当前书写板)——**永不出现板号参数**。方言里唯一的
数字空间 token 是顶部 `@board 2|3|4`。

**边界(进任务规格):** 单步高于一块板(巨型段落/超高图)→ 软放行 + `boardOverflow`
族 warning(巨型单步本身是坏讲稿);不硬截断。

### 1.5 「4 块写满怎么办」:**问题作废——答案是擦**(rev 1 附加的「末块向下延伸」补丁**删除**)

- **多块配置(2/3/4):** 板定高。全满且 agent 未显式擦除时,编译器**合成一次
  auto-erase**(擦最早写满的板,填充游标复位,书写继续)——老师写满四块自然回头
  擦第一块,常态动作,不必每次有仪式感。显式 `@erase` 是**表达**(「这块讲完了,
  放下」),auto-erase 是**继续讲下去的默认物理**——二者都是 canonical timeline 上
  的串行擦除单元,只是作者不同。这与「溢出自动换板」同构:空间调度归系统,
  表达归 agent。
- **单块配置:** 产品负责人原话锚定「单块**长条**黑板 = 现行线性模式」——单块形态
  就是向下生长的长条,**不触发 auto-erase**(长条不会满),退化等价免费成立。
  显式 `@erase` 在单块上仍可用(清场开新章)。
- 被否的其余候选:硬停报错(截断内容 + 逼 agent 管空间,双违规)、自动加第 5 块
  (破硬上限与隐喻)、缩小已写内容(重绘已示内容,毁可读性)。

## 2. 擦除模型 —— 逐项验证(本轮新增的核心判定)

### 2.1 G5 新表述(替换「内容累积、刻意不擦除」)

> **G5(新):板面可擦,历史不可擦。** 擦除是显式的、串行的表达动作,只能以
> **追加擦除指令**的方式发生;它改变板面此刻的呈现,不改变 canonical timeline,
> 也不触碰讲稿文件。scrub 回拖到擦除之前,被擦内容必须重现;课堂笔记遍历全部
> 内容步、忽略擦除步,永远大而全。任何**隐式**的内容丢失仍然违规——分页、滚动
> 替换、被动覆盖,以及**从 board.md 删除已播文本**(那是删历史,不是擦板)。

**与 G1:零冲突,互相强化**——擦的时候手不在写(产品负责人:「能擦能划掉,都是
串行的」);erase 单元占 schedule 独占时段,既有「零重叠 + 采样并发 ≤ 1」测试
原样覆盖。G1 表述随两轮修正合并为:**「一次只做一件事——写、划、擦、移镜头、
移板,五者同轴、互斥。」**

**与 R1–R8:零冲突,两条补充。** R1:追加 erase 步是**向前**的新动作,不是重播
已示内容;R8:erase 在 canonical 内,确定性不变。补充:(i) R4 族新规——被擦目标
步重建(hash 变)时,erase 单元持有的目标句柄失效,宿主须重链(与 chart 重建
级联同类,进既有 REBUILD RULE 文档);(ii) 纪律新规(进 SKILL.md 与 R 规则)——
擦除**只能追加指令表达**,从文件删除已播文本仍按 R4′ 降级处理且属违纪。

**语义配对(方言的表达力增量):**

| 动作 | 语义 |
|---|---|
| `~~划掉~~` / `@strike` | 我**否定**它,但留着给你看(先立、再驳、后划) |
| `@erase` | 它**完成使命**了,放下,腾地方(内容本身没有错) |

### 2.2 erase 的机制判定:是 `Revealable` 揭示单元,**不是**共享寄存器

协调人的怀疑(「擦除跟镜头一样属于共享寄存器」)**不成立**,且分界线值得立为
设计规则:

> **寄存器 vs 揭示单元的判据:状态所有权能否在编译期划成不相交集合。**
> 镜头/板位是「多步写同一个寄存器」——last-wins、顺序相关,只能走纯函数折叠
> (`stageStateAt`);擦除的目标可在编译期**唯一分配**——每个内容步至多被一个
> 擦除步擦(它之后第一个覆盖其所在板的 erase)——于是每个 erase 单元独占一组
> 互不相交的可见性状态,`Revealable` 分发安全。

**回放正确性验证(硬要求:「回拖到擦除之前,被擦内容重新出现」)。** erase 单元的
`seek(p)`:p=0 目标全可见、p=1 全隐、中间值 = 板擦扫过的进度(单调 easing,幂等
样式写)。对 `timeline.ts::makeSeek` 的窗口遍历逐情形检查:从 t=100 回拖到 t=20,
E1(t=50, 擦 C1)与其后写在同一位置的 C2(t=60)、E2(t=90, 擦 C2)都落在遍历窗口
[idx(20), idx(100)] 内 → E1.seek(0) 使 C1 重现,C2.seek(0) 归未写,E2.seek(0) 归
未擦——终态正确(t=20 时板上正是 C1)。窗口**之前**的内容单元无须重发(它们
p=1 的状态从未被自己改变,遮蔽它们的只有 erase 单元,而 erase 已回 0)。目标集
不相交保证与分发顺序无关。**结论:`Revealable` / `BoardTimeline` / `makeSeek`
零改动承载擦除**;唯一新增是 `MeasureContext` 的目标句柄 seam(镜像 `backRef` /
`chart` 既有形状——跨步节点操作经宿主 seam 进入是既定模式,chart 层写 frame 节点、
backref 墨迹画在他步文本上,都是先例)。

**一条 G8 级硬规则(通道不相交,漏掉即静默视觉 bug):** 目标**集合**不相交只保证
了 erase 单元之间互不干扰,还必须保证 erase 的**样式通道**与揭示策略的通道不相交。
反例:fade 策略驱动 `opacity`,若 erase 也用 `opacity` 隐藏——C 步 fade 揭示中
(t=10..12)、E@50 擦它、回拖 60→11 时窗口按索引升序分发:`C.seek(0.5)` 写
opacity 0.5,随后 `E.seek(0)`「恢复」opacity 1——C 变成全显而非半透。wipe 的
clip-path 同理。**修法:erase 必须独占一条与所有揭示策略不重叠的视觉通道**
(erase 专属 wrapper 元素或专属 class,`seek(0)` = 移除自己的状态,绝不写任何
策略拥有的属性)。与 G8-D(token 颜色走 `element.style`)同族:只在特定组合下
暴露、不报错、质感悄悄坏。

**auto-erase 的类型位置:不进 `Step` union。** 它没有源文本,若做成 Step 会破坏
「Lecture = 讲稿的纯 parse」。正确位置:**计划层合成单元**——`planStepUnits` 本就
合成无源构造的单元(heading 的手绘底线、list 的弹点是先例);auto-erase 作为触发
溢出的那个 step 的**前导单元**合成(「擦旧板,再写这步」),srcSpan = 该步的源区间
(G6 覆盖率保持 100%,高亮语义正确:此刻讲稿上正在写的那句话,就是逼出擦板的
那句话)。显式 `@erase` 则是有源 Step,正常入 union。

### 2.3 擦除粒度:v1 = **整块板**;单元级/区域级 → v2

- **推荐:** 裸 `@erase` = 当前书写板;`@erase "锚文本"` = 内容锚定到目标步所在板,
  整板擦除。理由:(i) 填充折叠保持平凡(游标复位;区域级擦除引入自由空间碎片
  管理,折叠复杂度陡增);(ii) 语义分工干净——「精确否定一句」已有 strike,
  外科手术式擦掉一句是 strike 与 erase 的怪异杂交,真实黑板上「腾地方」的单位
  就是板面;(iii) 板级目标让 erase 单元的目标集分配显然不相交(§2.2 的判据
  平凡成立)。
- **反方最强论据:** 老师确实会擦掉半块板。**回应:** v2 的区域级擦除可以在同一
  契约下加(目标集仍可编译期分配),v1 不为它付折叠复杂度。

## 3. 设计内核的形式化 —— 检验与采纳(随擦除修订)

产品负责人的三段式检验通过,采纳,带两处精确化:

- **墨迹是物质:** 画上去就长在那儿——**不可移动**(相对于它的板;板动墨迹随板走),
  **不可被隐式丢弃**;但可被**显式的擦除动作**放下。擦掉的墨迹从板面消失、在历史
  (timeline + 笔记)中永存。
- **舞台是可调度的:** 能动的是镜头姿态与各板相对位置(两个寄存器族);**板面内容
  的清空是表达动作**(揭示单元),不是舞台调度——这就是 §2.2 判据在产品语言里的
  样子。
- **二者同轴:** 写、划、擦、移镜头、移板全部是 canonical schedule 上的独占条目,
  同一条时间轴——「注意力引导 = 内容产生过程本身」由架构保证。

**`stageStateAt(schedule, t)` 推广确认(不破坏 rev 1 结论):** 舞台步(镜头/搬板)
不实现 `Revealable`、占 schedule 独占时段、`targets[]` 留空走 `makeSeek` 现成的
unpaired「dispatch nowhere」路径(零改动),姿态由纯函数折叠返回
`{ camera, panelOffsets[] }`,宿主每帧查询、按 camera-latch gate。擦除**不进**这个
折叠(§2.2)。

## 4. 契约冲击面(rev 2 全表)与三个初判终态

**初判终态:** A 证实(舞台化推广,§3);B 证实(板 = 区域,守卫更强,§1.3;
退化三门保留——parser 字节等价 / schedule 字节等价(seed 板快照为仪器)/ 像素等价
(`harness/screenshots/` 约 38 张截图为仪器));C 原样证实(draw.io 否:封闭静态
渲染器给不出 per-element schedule 分解 + srcSpan + 单一可描画路径;xyflow 否;
dagre 限 factory 层,确定性是测试门;G2 例外清单三处同步修订)。

| 契约 | 动不动 | 具体 |
|---|---|---|
| `Revealable` | **不动** | erase 单元是标准 Revealable(§2.2);舞台步不实现它 |

## 5. 方言(rev 2 汇总)

### 5.1 板面配置:顶部指令 `@board 2|3|4`

首个内容块前、独立成行;缺省 1 = 长条(现状);中途出现 → BadStep。读感 =
讲稿开头的舞台说明(「(三块板)」),与 `@wait`/`@strike` 指令家族同形。
**必须在 board.md 内的硬理由:** 板数喂布局折叠 → 布局喂墨迹几何与舞台状态,
全是 canonical 输入;放 viewer 设置或 sidecar 会让同一讲稿 canonical 不同,R8 破。
板逻辑**宽度恒定、与配置无关**(多块 = 定高并列同宽列)——这让笔记态与板态共享
测量(§6),也让退化门更稳。备选(front-matter:`---` 撞 rule 语法且引入元数据
机制;sidecar:讲稿读者看不见舞台形制、canonical 输入散到第二文件)均判弱。

### 5.2 动词全家福(表达动作 → 时间轴上的串行单元)

| 动词 | 语义 | 落位 |
|---|---|---|
| `@overview` / `@focus "…"` | 移镜头:我带你去看 | C2 |
| `@erase` / `@erase "…"` | 擦除:它完成使命了,放下 | C3 |
| `@bring "…"` | 搬板:我把那块搬过来并排看(重动作) | C3b |

全部内容锚定(就近匹配,backref 同款),**永不接板号**(§1.4 推论)。
契约先行原则:`stageStateAt` 的返回形状 **C2 就含板寄存器**(折叠契约后补重塑是
破坏性变更,方言动词后补是纯加法)。移镜头与搬板在方言里**分开**——视觉同为相对
运动,教学动作不同(带你看 vs 搬来并排),这是产品要求也是正确的词汇设计。

## 6. 板 ≠ 笔记:导出态评估(v1 就给)

**结构:** 二者共享同一份 canonical timeline。板(播放态)= 面积有限、会擦、
镜头引导;课堂笔记(导出态)= 遍历全部内容步、忽略 erase 与舞台步、线性平铺、
可滚可搜。**笔记态 ≈ 当前已实现的线性板**——现有 BoardCanvas 渲染路径的重新定位,
不是新机制。

**真实成本核对(公式/图表/墨迹的重排代价):≈ 零重排。** 笔记态 = 单列文档流,
正是现行实现的原生布局;板宽恒定(§5.1)⇒ 测量可复用;chart/graph 终态 =
`seek(1)`(累积容器本来就长在文档流里);原地墨迹随其文本;回指墨迹的几何本就
按目标步测量。唯一新工作:(i) 视图开关 + 过滤(erase/舞台步不参与笔记 build;**切换时重建**,
不做双活 build——factory 契约是 single-shot per mount generation,双活会翻倍
DOM 与构建),(ii) 笔记态的静态导出(「大而全的网页版」)。**建议:v1 给笔记视图**(in-viewer
开关,估 100–200 行,复用度 ~全部);**静态 HTML 导出随 export routes 既有设施
v1.5**(序列化 + 内联 theme.css,中等;不 gate 方向)。

**反方最强论据:** v1 再加一个视图会不会稀释交付焦点?**回应:** 笔记视图在擦除
落地(C3)之前**就是板本身**——它作为独立视图的意义随 C3 才出现,所以它的落位是
C3 包内的一个开关,不是提前的新面。
