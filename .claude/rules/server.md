# Server / CLI / Core Rules (Bun + Hono)

## Baseline

- **Bun APIs** over Node.js (`Bun.spawn`, `Bun.file`, `Bun.serve`, …). Runtime is Bun >= 1.3.14, not Node.
- **Contract-first**: contract changes → update `core/types/` + `core/__tests__/` + `docs/reference/` + the contracts table in `docs/reference/project-guide.md`, in the same change.
- **No hardcoded mode knowledge** in server/CLI — everything driven by ModeManifest. **No backend conditionals** (`if (type === ...)`) outside `backends/index.ts`.

## Gotchas

- **Session paths and registry ownership**: `resolveSessionPaths` in `core/path-resolver-pneuma.ts` owns the path policy. Quick sessions have `sessionDir = workspace` and `stateDir = workspace/.pneuma`; project sessions have `sessionDir = stateDir`. Skills and instructions use `sessionDir`; runtime metadata uses `stateDir`. Registry atomic writes prevent partial reads, but multiple processes still perform read-modify-write and can lose updates. Scanning sessions inside a registered project does not restore missing global registration. See `docs/reference/controlled-state-surface.md` for recovery and deletion paths.

- **The workspace watcher is one layer with two backends** (`server/watch/`, 2026-09-24): `native` (one recursive `fs.watch` per root; macOS default) and chokidar 5 (prunes before traversal; Linux/Windows default and the fallback on registration failure or ENOSPC/EMFILE). `PNEUMA_WATCHER=native|chokidar` overrides. Backends only report "something happened at rel"; the layer applies the ignore to every notice and its ancestors, classifies by `lstat` (FSEvents types every event `rename`), owns the 200 ms write stability, and rescans on overflow. Its file index is taken synchronously at creation and reconciled once the backend is ready, so a change made after `createWorkspaceWatcher()` returns is reported even if the backend was still registering (chokidar's `ignoreInitial` hid them); the index also turns a directory moved in or out into per-file events. A path exists only under its on-disk spelling (after a case-only rename on APFS/NTFS, `lstat` of the old name still succeeds), and an index entry now a directory is gone. A non-ENOENT `lstat`/`readdir` failure is logged and sets `degraded`; `ready` waits for a fallback's replacement. `startFileWatcher`, `startProxyWatcher` (`proxy.json` never ignored) and `projects-cache` subscribe. The layer reports every vanish, with `known` (indexed at creation or reported since); `startFileWatcher` sends a delete when `known` or when a browser may hold the path (the `/api/files` snapshot listed it, or an update carried it). Scratch files are neither (they once sent one delete frame each), while an unchanged image a page displays is `known` (filtering on held paths alone left doc mode showing a deleted picture). Ignore globs are compiled by `buildIgnoreMatcher` (Bun.Glob, workspace-relative, `x/**` also matches `x`) and reach chokidar as a function: its v4+ string entries are exact-equality, which once disabled every default ignore. Health: `GET /api/session` → `watcher`; a probe `.md` write must move `lastEventAt` (`/api/files` reads disk and proves nothing). Every incident is a case in `server/__tests__/watch-contract.test.ts`. Records: [Watcher backend](../references/server-gotchas.md#watcher-backend).
- **One `fs.watch` per root, never per path, no watch churn at runtime** (2026-09-24): under Bun on macOS all `fs.watch` calls share one FSEventStream that Bun rebuilds from "now" on every add or close, losing events in the gap (~20-40 ms at 1,200 paths). chokidar's per-path watches opened a hole on every `writeJsonAtomic`, so backlot's `cut --finish` never reached the viewer, and a native watch added beside chokidar went deaf too. Register each root once, and register startup watches before the workspace watch (`bin` calls `primeRegisteredProjects` first; priming after it lost 6 of 29 early edits). A later registration or close (a project registered mid-session) makes every other live watcher reconcile 100 ms after it, which recovers what the gap dropped. Churn has also left a fresh watch receiving no callbacks at all (test churn only): never create and close watchers in a loop. At process exit leave watchers open (`bin` skips the workspace watcher and calls `cleanup({ exiting: true })`): closing chokidar's per-path watches took 2.7 s against the 4 s fuse that guards killing the agent. Records: [Watcher backend](../references/server-gotchas.md#watcher-backend).
- **Project-cache watchers must not traverse session content**: every session server primes all registered projects, and a watcher that visits each session's content, captures and dependency directories once stalled a new session's first HTTP response by tens of seconds. The layer's ignore predicate prunes (chokidar) or drops in JS (native) everything but the metadata the scan reads. Keep real watcher tests for content isolation and for atomic metadata replacement, history/thumbnail writes, and session creation/removal. Measurements: [server records](../references/server-gotchas.md#project-cache-watcher-stall).

- **Slash command 必须原样到达 backend,别往它前面拼任何东西**:`prepareIncomingUserMessage` 会把会话打开时排队的 `<pneuma:env reason="opened"/>` 折进下一条用户消息前面,前端 `src/ws.ts` 还会拼 `<viewer-context>` / `<user-actions>`。三个 backend 都按 turn 的**开头几个字符**识别命令(Claude Code 展开 `.claude/commands/*.md`、Codex adapter 拦 `/compact` 走 `thread/compact/start`、Kimi 对 ACP 命令表),所以开会话后第一条就发 `/compact`,agent 收到的是 `<pneuma:env …/>\n/compact`,模型把它当成一句关于上下文的提问回答了(实测 2026-09-07)。判定统一走 `core/utils/slash-command.ts::isSlashCommandMessage`,两层都豁免;被扣下的 env 上下文留给下一条普通消息,不丢。
- **Quick session 的注册表 id 是 `workspace::mode`,但磁盘上一个 workspace 只有一个 `.pneuma/`** —— 两层对同一件事的说法不一样,而且这个分歧今天就在咬人。`bin/pneuma.ts` 启动时 `loadSession(stateDir)` 读到的是**这个目录上一次跑的那个 mode** 的 `session.json`,**没有任何地方比较过 mode**:于是在同一个目录起第二个 mode,它的 `agentSessionId` 会被当成 `resumeSessionId` 传下去,**新 mode 接着旧 mode 的对话往下说**,然后把 `session.json` 的 mode 覆盖掉。3.43.0 起,quick session 只在**带着 staged inbound-handoff 启动**时才判定为"另起一个"(`startsOverPersistedSession`),此时不 resume、不继承 backend、`saveSession(..., freshStart)` 也不再从旧文件里继承 `displayName`/`description`/`internal`/`borrow`(否则新会话会顶着上一个会话的标题)。**手动在同一目录换 mode 仍然会误 resume** —— 那条路没有 inbound 可判,要修得引入别的判据,别以为这条 gotcha 已经全好了。
- **inbound-handoff.json 的路径是从 agent 的 cwd 推的,不是从 stateDir 推的**:project 会话 `<projectRoot>/.pneuma/sessions/<id>/.pneuma/inbound-handoff.json`,quick 会话 `<workspace>/.pneuma/inbound-handoff.json`。两者都是 `<sessionDir>/.pneuma/...`,只是 quick 的 `sessionDir` 就是 workspace 本身。**写错的失败形状是静默的** —— target 正常启动、看不到任何 handoff,而不是报错;3.10.9 之前 `handoff-from-external` 就因为误以为 quick 的 sessionDir 是 `<workspace>/.pneuma` 而多套了一层。handoff confirm、`handoff-from-external`、`readInboundHandoff` 三处必须同时遵守同一条规则。
- **从 quick session 发起的 handoff 不升格 project,也不建立任何联系**:它把这个 workspace 交给一个新的 quick session —— 不写 `project.json`、不迁移旧状态、不写 `switched_out`(那条 history 马上就要被新会话覆盖)、不预先 mint session id(quick 的 id 由会话自己在启动时生成,所以 confirm 的响应里 `target_session_id` 是 undefined,浏览器靠 `launchUrl` 跳转)。唯一的痕迹是新 `session.json` 里的 `sourceSessionId`,而且**没有任何读者去追它**。需要共享 preferences、文件与面板的两个会话,那是 project 的职责 —— 别把 project 的语义偷偷塞进 quick。


- **Seed 拷贝的「二进制判定」是 `server/seed-installer.ts::isBinarySeedFile` 一处说了算,别再就地写扩展名正则**(2026-09-20):旧规则是一张**二进制扩展名白名单**,不在名单上的一律 `readFileSync(utf-8)` → `applyTemplateParams` → `writeFileSync(utf-8)`。方向反了——名单漏一个格式就静默损坏,而且只在 mode **有 init params** 时发作(没有 params 时整段走 `copyFileSync`,所以自测很容易看不见)。backlot(出事时还叫 previz)的 seed 里 `scene.glb` 386,200 → 630,493 字节、`scene.blend` 186,934 → 337,171,全是非法 UTF-8 被换成 U+FFFD 撑出来的,退出码 0、没有任何警告,表现是「拷进工作区的模型打不开」。现在的规则:扩展名当**快速路径**(已扩到 glb/blend/bin/webm/mov/m4a/flac/otf/avif/wasm/7z),未知扩展名再**嗅探前 8 KiB 有没有 NUL 字节**——文本永远没有 NUL,我们发的每种二进制容器 header 里都有。两个调用点(`copySeedEntry` 的目录/单文件两支、`bin/pneuma.ts` 里 `_` 前缀 seed 的每次启动 re-sync)必须调同一个导出函数;`server/index.ts` 的 `registerSelfWrite` 注释也指着它。判据:带 params 跑一次 `copySeedEntry`,对 seed 里每个文件做 `a.equals(b)`,别只看有没有报错。

- **Every workspace read, write, and delete goes through `server/utils.ts::isContained`** (2026-09-23 final review, findings 13/18/19): it compares whole path components and canonical targets, so an in-root symlink whose target stays inside is fine and anything reaching outside (`..`, `<root>-neighbor`, a link) is refused. `canonicalPath` fails closed — `null` for a loop, more than 40 links, a non-directory component, or any error but ENOENT; a missing suffix of any depth is appended to the realpath of the nearest existing ancestor (the old depth cap returned the lexical path, so `link-out/d0/…/d34/x` wrote outside). The boundaries: `/content`, `/api/file(s)`, scaffold, content-set delete, seeds (`planSeedEntry` checks the whole set before writing), every export builder (content-set root, manifest, manifest-named files, inlined assets, zip trees), the watcher (outside targets are never read or sent), asset/setup listings, replay checkout, mode showcase/bundle assets, project file/thumbnail/session-delete, `git/diff`. Validate the complete target set before destructive work. Deliberate exceptions: `resolveOsHandoffPath` and project-management actions. Check-then-use is not atomic (a local race can swap a path for a link). **Git is a second interpreter** (round-4 finding 22): a checked path handed to git is still a pathspec — `:(top)x`, `:/x` or a glob reach outside a workspace nested in a larger repo, and `--` does not disable magic — so git calls take `--literal-pathspecs` plus the normalized checked relative path, list with `--relative` / `-- .`, and request- or package-supplied object names pass `isGitObjectId` (refs: `isSafeGitRef`) before any argv, since a leading `-` is an option (`git archive --output`, `git fetch --upload-pack`). Tests: `path-containment`, `workspace-containment`, `export-containment`, `asset-listing-containment`, `git-routes-containment`, `file-watcher`.
- **Bun.serve dual-stack**:必须 `hostname: "0.0.0.0"`,否则 macOS IPv6/IPv4 端口碰撞。
- **Stale `dist/`**:若 `dist/index.html` 存在,server 退回 production 模式。要么删 `dist/`,要么传 `--dev`。Launcher 派生子进程自动继承 `--dev`。
- **Vite WS proxy + Bun.serve**:浏览器 WS 直连 backend 端口,绕开 Vite。
- **Shadow-git checkpoint queue**:所有 checkpoint 操作通过 Promise chain 串行化,防 `index.lock` 冲突。**不要并行**。
- **Shadow-git 自引用爆炸(O(N²) 磁盘吞噬)**:shadow repo 的 work-tree 是 `workspace`,排除规则写在 `info/exclude`。**Project session 里 `workspace === stateDir === sessionDir`**(`path-resolver-pneuma.ts` + `bin/pneuma.ts` 的 `workspace = sessionDir`),于是 `shadow.git/` 本体、`history.json`、`.claude/` 等全在 work-tree 根。旧规则只有 `.pneuma` 一条(为 quick session 写的,那时状态在 `.pneuma/` 子目录),在 project 拓扑下**一条都不匹配**——每轮 `git add -A` 把 shadow.git 自己越来越大的 object store 再 commit 一遍,叠加 auto-gc 的 ~GB 级 repack,体积按 O(N²) 爆炸(实测一个 37-turn 的 session 到 27 GB,99.96% 是 `shadow.git/objects/pack/*.pack` 的自我快照)。修复三件套:(1) `buildExcludeRules` 按拓扑派生——`resolve(stateDir) === resolve(workspace)` 时追加 root-anchored(`/session.json`、`/.claude/`、`/CLAUDE.md`…)的 plumbing 排除,base 始终含 `shadow.git`/`checkpoints.jsonl`/`.venv` 等;(2) `initShadowGit` 幂等分支(resume)**也要重写 `info/exclude` + `git rm -r --cached --ignore-unmatch`**,否则旧 session 永远拿不到新规则;(3) `captureCheckpointInner` 加 `MAX_CHECKPOINT_FILE_BYTES` 单文件上限。**测试必须用 `workspace === stateDir` 复现真实 project 拓扑**——老测试传 `workspace=projectRoot、stateDir=更深子目录`,`.pneuma` 规则恰好生效,所以从没抓到。已爆的 repo 只能 re-init 回收(`git gc` 无效,自引用 blob 从 HEAD 可达);删 `shadow.git` + `checkpoints.jsonl`,下次启动重建,work-tree 内容不动。
- **Proxy**:(1) `proxy.json` 由 session 的 workspace watcher 热加载(启动后才创建的也算)。(2) 默认只放行 GET——POST/PUT/PATCH 要求显式 `"methods"`。(3) Bun `fetch()` 自动解压 gzip/br;proxy 必须剥 `content-encoding` 防双重解压。
- **Editor-open 策略**(`server/editor-bridge.ts`):文件走 CLI-first,**目录(项目根)走 `open -a`**。四条铁律:
  0. 目录目标必须 `open -a <App> <dir>`,不走 CLI——bundled `cursor <folder>` 经已运行实例 IPC 打开会崩最新版 Cursor 的 AgentPanel。`openInEditor` 里 `statSync(absPath).isDirectory()` 分派。
  1. 必须 sanitize env(`cleanEditorEnv`):剥 `VSCODE_IPC_HOOK_CLI` / `VSCODE_GIT_*` / `GIT_ASKPASS` / `ELECTRON_RUN_AS_NODE` 一族,否则 bundled 启动器切 remote-IPC 模式崩 Cursor。
  2. 开文件时传 enclosing folder 作前导位置参数以聚焦已有窗口(`buildOpenArgs` + `findProjectRoot`)。**不要用 `-r/--reuse-window`**。
  3. 行号方言:VS Code 系 `--goto <file>:<line>`,Zed/Sublime `<file>:<line>` 后缀(按 `KnownEditor.family` 分派)。`open -a` fallback 只能裸路径。
- **Native bridge timeout**:`/api/native/*` 经浏览器 WS 路由——若无浏览器 tab 连接,native call 10s 超时。Web 返回 `{ available: false }`。
- **解析别人的 banner 之前先剥 ANSI**(与上面 PATH capture 同一类,但独立踩过一次):`startViteDev` 从 Vite stdout 认端口的正则是 `/Local:\s+.../`,而 Vite 给 banner **上色到 token 内部**——真实行是 `Local\x1b[22m:   \x1b[36mhttp://localhost:\x1b[1m17999`,`Local:` 和端口数字**都**被转义序列切断,于是**从来没匹配上**:每次 dev 启动都走满 10 秒超时,然后回退成「**我请求的**端口」而不是「Vite **实际绑定的**端口」。17996 被别的 session 占着时,`[pneuma] ready` 打出的 URL 指向**别人的工作区**——盲测里一个冷启动 agent 因此找不到自己的页面,还在 17999 上对着另一个 session 的板子操作并收到「成功」。修法是 `parseVitePort()`(纯函数、导出、按真实带色行测试):**先 `replace(/\x1b\[[0-9;]*[A-Za-z]/g, "")`,再匹配**。任何解析第三方 CLI 输出的地方照办;超时回退到「请求值」这种 fallback 尤其毒,因为它长得像成功。 Vite exiting before its `Local:` line now rejects (exit code + output tail); only a live, silent Vite falls back, with a warning. Port binding likewise: `server/bind-port.ts::bindFirstFreePort` throws when the whole range is taken, so `startServer` rejects and the CLI exits 1 instead of printing ready for an unbound server.
- **Shell PATH capture 有两个跨 shell 陷阱**(`server/path-resolver.ts` + `desktop/src/main/bun-process.ts` 各一份,`rootDir: "src"` 挡住了复用,**改一个必须改另一个**):(1) **marker 不能贴着变量名**——`"___PATH_START___$PATH___PATH_END___"` 里下划线是合法标识符字符,bash / zsh / fish **一致地**把它读成名为 `PATH___PATH_END___` 的变量(恒空),正则永远匹配不上,函数每次静默 fallback。marker 必须独占一行。(2) **必须用 `printenv PATH`,不能用 `echo $PATH`**——fish 把 PATH 存成 list,`echo $PATH` 用**空格**而非冒号连接。另外 `-i` 会加载交互式 rc,fastfetch 之类的 greeter 会往同一个 stdout 写 ANSI 图形,所以捕获结果必须剥 ANSI **并校验**(至少含一个真实存在的绝对路径目录),否则会把开屏 logo 当 PATH 用。这套 bug 长期隐形:终端启动时 `process.env.PATH` 本就正确,`buildFallbackPath()` 又覆盖了常见目录;只有「GUI 启动(Electron 的 PATH 是最小集)」+「二进制在硬编码 fallback 列表之外」同时成立才发作(实例:Kimi Code 改装到 `~/.kimi-code/bin`,而旧版在 `~/.local/bin`,于是表现为「升级后 CLI 突然找不到」)。**新 agent CLI 若装在非常规目录,除了修 capture 还要往 `buildFallbackPath()` 补一条**;`getEnrichedPath()` 现在无条件把 fallback 追加到最低优先级作兜底。
- **Backend lifecycle 测试是 live-LLM 集成测试,会 flaky**:`backends/*/__tests__/lifecycle.test.ts` 跑真实 CLI + 真实模型,单次失败(超时、`apply_patch verification failed` 之类)**不足以判定回归**。判定前至少重跑一次,或与干净树对比两次以上——单样本对比会得出相反结论。
- **Windows 兼容**:散在 `path-resolver.ts`(`where` vs `which`)、`terminal-manager.ts`(`COMSPEC`)、`system-bridge.ts`(`cmd /c start`)、`server/index.ts`(`NUL`、`taskkill`)。win32 路径比较不区分大小写。
- **Machine-readable CLI subcommands bypass `p.intro()`**:`agent-command`、`mode list --local`、`handoff-from-external` 在 `bin/pneuma.ts:main()` 里**先于** clack banner dispatch,否则 banner 污染 stdout 让 agent 侧 `JSON.parse` 挂掉。未来任何 stdout 被 agent 消费的子命令都得照办。
- **`pneuma handoff-from-external` detached spawn**:必须给子进程传 `--no-prompt`。`stdio: "ignore"` + `detached: true` 下子进程没有 stdin;任何 `init.params` prompt 都会永久阻塞。
- **`--skip-skill` 曾经连 `/borrow` `/handoff` 一起跳过**:两条 session-scoped slash command 原本写在 `installSkill()` 体内,而 `bin/pneuma.ts` 的 `skipSkillInstall`(resume 时用户选「保留当前技能版本」、`--replay`、`--viewing`)会把整块跳掉——于是一个 resume 过的 session 交接机制全在(CLI、路由、卡片都在),**唯独 agent 没有入口**,表现成「升级到 3.43.0 了但 `/handoff` 看不到」。判别方法:`ls <sessionDir>/.claude/commands/`,不是去查前端过滤(前端不过滤,`ChatInput` 直接映射 `session.slash_commands`)。现在这一步是独立的 `installSessionCommands(installTarget, backendType)`,skip 那条腿也调,且必须在 **agent spawn 之前**——Claude Code 只在启动时扫一次 `.claude/commands/`,不热加载。判据是**谁跟谁一起发版**:session command 在 `templates/`、随 pneuma 发版,所以不能被「关于 mode skill 的决定」左右;紧邻的 workflow scripts 在 `modeSourceDir`、随 mode skill 发版,拒绝技能更新时保留旧脚本才是对的——**别把那块也提出去**。
- **Handoff confirm 不能 kill 自己 session**:`killActiveSession(sourceSessionId)` 跑在源 session 自己的 server 里,但源进程是 launcher 派生——源 backend 继续跑。桌面端靠 mode-window 关闭时按端口对照 `/api/running` 批量 teardown 缓解。
- **Project session 状态污染 if `--project` 丢失**:subcommand 不解析 `--project` 会把状态写进 project root 与项目层冲突。所有 subcommand(含 `evolve`)必须尊重 `--project`。
- **Project session id vs backend id**:`session.json` 顶层 `sessionId` 是项目 session id(= 目录名 = URL `--session-id`);backend 协议 id 在 `agentSessionId`。**绝不让 backend id 泄漏到 registry / panel**,否则解析到不存在的目录。
- **Launcher 没 agent session,WS 广播到不了**:`WsBridge.broadcastAll` 按 per-session 浏览器 socket 遍历;launcher main page 在任何 session 存在之前就 mount。Launcher-scope mutation 路由必须在本地 dispatch DOM event(如 `pneuma:libraries-updated`);真实 session 内的 sibling tab 仍走 WS——两条路径汇到同一事件名。
- **Backend persistence**:`backendType` 在 `.pneuma/session.json` 和 `~/.pneuma/sessions.json` 都是 resume identity 的一部分。Backend 在 startup 选定后 session 内不可切换。
- **Refined session meta 双写,resume 必须保留**:`pneuma session refine` 把 `displayName`/`description`/`refinedAt` 同时写进 registry entry(`~/.pneuma/sessions.json`,launcher Recent Sessions 读)**和** canonical `session.json`(ProjectPanel 经 `scanProjectSessions` 读)。任何在 launch/resume 时**从头重建**这两处条目的路径都会把这三件套擦回 mode 默认("WebCraft session" + 首条消息预览)——`recordSession`、`saveSession`、`importSessionsIntoProject` 三处都犯过。Registry 侧用 `pickRefinedMeta`(`refinedAt` 是 "已 refine" 标记),session.json 侧用 `preserveRefinedSessionMeta`,二者均"显式传入值优先、缺省回退旧值"。同一陷阱早有先例:`sessionName` 走 `pickSessionName`。新增任何 session-entry rebuild 路径,先想清楚这四个 user/agent 设定的字段怎么保留。
- **Replay**:(1) `--replay` 推迟 agent 启动到 `/api/replay/continue`。(2) 每次 checkout 前清 `.pneuma/replay-checkout/`。(3) 文件 navigation 必须在 checkpoint 加载**之后**(不能在 `displayMessage` 期间)。
- **Editing/readonly distinction**:`editing` 是 session 布尔(`true`=创作,`false`=消费),`false` 时不跑 agent;`readonly`(replay)禁用一切交互。两者不要混。
- **Bun `os.homedir()` 启动时缓存**:boot 后改 `process.env.HOME` 不会改 `homedir()` 返回值。需要 tmp home 的模块改读 `process.env.HOME ?? process.env.USERPROFILE ?? homedir()`。
- **启动强制写 `~/.pneuma/sessions.json`,任何禁止写 HOME 的沙箱里 Pneuma 起不来**(2026-08-14 实测,Codex 托管环境):registry 的 upsert 走原子写(临时文件 + rename),沙箱只允许写工作区内部时,它在 `open('~/.pneuma/sessions.json.tmp.<pid>.<rand>')` 上拿到 `EPERM` 并且**直接 fatal**——不是降级、不是警告,进程退出码 1,而此前的 skill 安装、端口选择、banner 全都已经打印过了,所以日志读起来像"启动成功后突然死掉"。受影响的不止 Codex:任何 CI runner、容器、或把 HOME 只读挂载的环境同理。**要在受限环境里跑,得先想清楚 registry 是不是可选的**——它今天是必需的,而这是个产品决定,不是实现细节。顺带:Codex 自己也要写 `~/.codex`,同一堵墙。
- **Bun <= 1.3.13 在 macOS arm64 上会把整个 server 死锁**:chokidar 监听的工作区里高频 mkdir/rename/rmdir(plotwise 播放时的后台预生成正是这种负载)会触发 Bun 运行时的锁序倒置(oven-sh/bun#26762,mimalloc v3 升级修的),症状是主线程与 `File Watcher` 线程都停在 `_os_unfair_lock_lock_slow`、0% CPU、路由与 WS 全死、Vite 还活着。所以 `engines.bun`、`bin/pneuma.ts::checkBunVersion`、CI `setup-bun`、`desktop/scripts/download-bun.mjs` 四处都要求 >= 1.3.14,**四处必须一起动**——桌面端自带 Bun,用户升级本机 Bun 救不了桌面 app。别在应用层「绕」这个 bug。复现与各版本数据:[server records](../references/server-gotchas.md#bun-file-watcher-deadlock)。
- **返回 Blob 体的路由,Range 分支不能依赖 `Bun.file().slice(a,b).stream()`**:Hono 的 `cors()` 等中间件会 `new Response(res.body, …)` 重包一次,而切片后的 blob stream 在 Bun 1.4.0 上吐出整个文件——`Content-Range` 说 1 KB、body 却是整份,Chrome 判媒体不合法(`MediaError.code === 4`),视频 seek 全失败而已缓存的 clip 照常能放。Range 分支用 `Readable.toWeb(createReadStream(absPath, { start, end }))`;stream 体由 `Content-Range` 给总长。凡是返回 Blob 体的路由,测试要**在和生产相同的中间件链下读 body 字节数**,只查 header 的测试在坏版本上照样全绿。细节:[server records](../references/server-gotchas.md#range-responses-and-blob-slices)。
- **工作区里的 virtualenv 曾经让文件监听无声死掉**:`DEFAULT_IGNORE` 必须与 `shadow-git.ts::BASE_EXCLUDE_RULES` 对齐(`.venv`/`venv`/`__pycache__`/`site-packages`/`*.pyc`/各种 cache),**两张排除表以后要一起改**;mode 的 brief/SKILL 要明说「环境建在工作区外」。native 后端不能剪枝,被忽略子树里的洪水照样送进 JS 再丢掉(5,000 次写入的开销实测约 20 ms CPU)。事故记录:[server records](../references/server-gotchas.md#virtualenv-kills-the-file-watcher)。
- **给 mode viewer 打 bundle 只有 `snapshot/mode-build.ts` 一个入口,改它之前先认下 Bun 1.4.0 的两个解析坑**(2026-09-22 实测):(1) **`onResolve` 对 bare specifier 返回 `null` 不等于「交回默认解析器」,而是把这条 import 丢掉**——build 照样退出 0,bundle 里留一个未定义引用(react-markdown 打出来 74 KB,里面写着 `unified is not defined`)。只有 path-like specifier 返回 null 才安全,所以 host-dependency fallback 的 filter 必须窄到只看见 mode 自己源码里写出来的包名(`collectModeBareImports`);被这个扫描漏掉的名字退化成 Bun 自己的 unresolved-import **构建错误**,而不是静默坏包。(2) **external 的 import 保留原始 specifier**,所以不能把 `../../../src/store.js` 就地标 external——浏览器会去 fetch 一个不存在的路径。宿主 store 的所有写法统一路由到一个生成的 stub 模块,由 stub 去 import importmap 里那个 bare specifier;stub 自己的 path 必须与它 re-export 的 specifier 不同,否则 Bun 报 `Detected cycle while resolving import`。两条都钉在 `snapshot/__tests__/mode-host-abi.test.ts`,ABI 表本身见 project-guide contracts 表的 **Mode viewer host ABI** 行。**这个 builder 是 catalog mode 的发布路径**,它坏掉的形状是「下载回来的 mode 在浏览器里白屏」,不是构建失败。(3) **external import 的名字 Bun 不做链接检查**——`import { version } from "react"` 对着一个不导出 `version` 的 shim 照样构建成功,浏览器里 `does not provide an export named` 直接让 mode 卡在 Loading…(3.52.0–3.52.2 的 draw、clipcraft 就是这样,手写的 React shim 漏了 `version` / `useInsertionEffect`)。所以 React 家族的 shim 导出名从宿主包本身枚举,`buildModeViewer` 构建后用 `findUnresolvedHostAbiImports` 把产物对 shim 链接一遍,缺名即构建失败;别再往 shim 里手写名单。
- **The file snapshot and `content_update` carry text only** (`server/workspace-text.ts::readWorkspaceText`, 2026-09-23): `viewer.watchPatterns` decide which files `GET /api/files` and the watcher report, and a directory glob matches binaries. Both used to `readFileSync(path, "utf-8")` every match into `content` — plotwise's `**/nodes/**/*` made a 1.17 GB snapshot, sprite's `**/motions/**/*` 1.89 GB that Chrome aborted, leaving the viewer on its empty state. A binary match (known media/font/archive extension, or a NUL in the first 8 KiB) now arrives as `{ path, content: "" }`, the image-signal shape; its bytes come from `/content/*`. SVG stays text. Still list only what a viewer reads as text: large *text* files are not capped. Check: `curl -s -o /dev/null -w '%{size_download}' http://localhost:<port>/api/files`. Records: [server records](../references/server-gotchas.md#binary-files-in-the-snapshot).
- **List bulk per-frame output in `viewer.ignorePatterns`**: the native backend's start-up does not grow with file count (one registration, then an index walk: 72-79 ms on a 534-directory / 14,327-file backlot tree), but everything watched is still indexed, snapshotted by `GET /api/files` and, on the chokidar backend, registered one `fs.watch` per path (superlinear on macOS: a sprite workspace with 2,882 watched files answered nothing for 25-40 s). Patterns ending `/**` also prune the directory itself. Signal "a run landed" through a watched text file — sprite: `project.json` plus each frame's `createdAt` in its URL; backlot: its render revision. Records: [server records](../references/server-gotchas.md#watcher-registration-cost).
