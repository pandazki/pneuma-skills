# Pneuma WebCraft Mode — Third-Party Notices

## Design intelligence: pbakaus/impeccable

The `skill/` content of this mode (the SKILL.md design-intelligence section,
all `references/cmd-*.md` command bodies, the standalone `references/*.md`
topic references, and `skill/scripts/palette.mjs`) is adapted from
[pbakaus/impeccable](https://github.com/pbakaus/impeccable)
("Impeccable.style") under the Apache 2.0 License.

**Synced against:** impeccable skill-v4.1.2 (August 26, 2026) — the core, the craft floor,
the new-work flow, the visitor modes, the ban list, and all 22 `cmd-*.md` command bodies.

### Local adaptations

The pneuma-webcraft mode lives inside Pneuma's live-preview runtime,
which already provides the visual environment that upstream's slash
commands, browser decision page, and `npx impeccable` CLI/extension wrap
around. To fit that, the upstream content is adapted as follows:

| Upstream | Pneuma-webcraft adaptation |
|---|---|
| One skill per verb (`/<verb>` slash command) up to v2.x; consolidated into a single `impeccable` skill with verb-arg routing in v3.0, and a Commands table in v4 | All verb bodies inlined as `references/cmd-<verb>.md`; the agent reads them on demand. The toolbar keeps the grouped command list (Setup / Plan / Review / Refine / Performance / Style / Architecture) rather than upstream's flat table — the grouping mirrors the viewer toolbar the user actually clicks. |
| A much leaner always-loaded core in v4.0.0 (`SKILL.src.md` 188 → 85 lines), with depth loading on demand, because current models follow short structured instruction better than long insistent prose | Mirrored. The design-intelligence core dropped from ~200 lines to ~65: the quality floor, the ban list, the model-tell bans, and the AI Slop Test moved out of SKILL.md into `references/craft-floor.md`, which is loaded immediately before editing UI and not at all for planning-only work. SKILL.md's Pneuma half (viewer protocol, content sets, image generation) is unchanged in role but trimmed. |
| Four visitor modes — Persuade / Operate / Read / Experience — replacing the brand/product register (v4.0.0); `reference/brand.md` and `reference/product.md` retired, `reference/operate.md` added | Mirrored. `references/brand.md` and `references/product.md` are deleted; the four modes live in SKILL.md's Modes section, `references/operate.md` carries the Operate/Read depth, and the Persuade/Experience depth (font selection procedure, reflex-reject faces, color strategy, calibration) lives in `cmd-craft.md`'s "Commit the world" — the same place upstream puts it (`new-work.md` §4). |
| `reference/interaction-design.md` retired in v4 with no standalone successor | **Not mirrored** — the file is kept. Upstream's replacement is a single "States" line in `craft-floor.md`; the 189-line forms / focus / loading depth has no other home here, and the command references still cite it. |
| `reference/new-work.md` + `reference/routing.md`: job-kind routing (blank slate, new page in an existing product, section added to a working page, redesign, scoped refinement), each with a different freedom budget | Adopted as the body of `cmd-craft.md`, plus a condensed job-kind ladder in SKILL.md's Routing section. Upstream deprecated `/impeccable craft` because it infers the job kind from the description; **our entry point is the viewer toolbar, so the `craft` command id stays** and its reference is the new-work flow. All 22 command ids are unchanged. |
| `reference/craft-floor.md` (v4): the quality floor, plus the v4 bans — kickers/eyebrow labels, system display faces as display voice, unicode glyphs as icons, hard offset shadows outside neobrutalism, geometric-mask fake cutouts | Adopted as `references/craft-floor.md`, with the v3-era Pneuma bans (cream/sand default ground, numbered section markers, side-stripe borders, gradient text, text overflow) folded in so nothing is lost in the move out of SKILL.md. |
| Twelve new deterministic detector rules in v4.0.0 (58 total): glow halos and accent spotlights, marquee scrollers, blinking terminal cursors, decorative dot and grid fields, text under an overlay, first-viewport overflow, stock-geometry hero art, widened hover / nav-CTA / chip contrast and inset-shadow side stripes | The rules are ported as **agent-readable bans** in `craft-floor.md` — same treatment the v3.5.0 detector rules got. The detector itself is not adopted (see below). |
| The five-block direction contract written into the artifact before code (THESIS / OWN-WORLD / STORY / FIRST VIEWPORT / FORM), plus the FINISH exit-condition line (v4.0.0) | Adopted in `cmd-craft.md` §5. Upstream's FORM block cites the seed key printed by `concept-seed.mjs`; ours cites the form's position on the ordered candidate list and the `palette.mjs` seed when one was used. The FINISH line drops upstream's raster-provenance clause (which is discharged by `embed-prompt.mjs`) and keeps what webcraft can actually audit: finish review, verdict, DESIGN.md. |
| The finish review as a separate agent, ending on a derived verdict — `rebuild` / `fix` / `ship` / `recapture` — scored from recaptured screenshots (v4.0.3–v4.0.4) | Adopted in `cmd-craft.md` §7, with browser-overlay evidence replaced by the Pneuma viewer's `capture` action, exactly as the v3.9.0 critique adaptation does: run as an isolated sub-agent when the backend exposes a Task tool, otherwise disclose `DEGRADED: single-context finish review`. `recapture` is folded into prose (an invalid capture is evidence of nothing, and no verdict may rest on it) rather than being a fourth reported word. Upstream's "desktop and mobile together" round is rewritten for our surface: `capture` shoots the live viewer at its current viewport, so responsive claims are verified by reading the real breakpoints, or by asking the user to flip the viewport — the agent is never taught to claim evidence it cannot produce. |
| Surfaces remember their strategy in `.impeccable/surfaces/` (v4.0.0), written and read by helper scripts (`surface-brief.mjs`) | Adopted as **agent-driven** Write/Read behavior (same shape as the critique-snapshot row below): SKILL.md teaches the path, the small fixed contents, and the read-before-you-touch-the-page rule. No helper script ships. |
| `PRODUCT.md` gaining positioning, evidence on hand, and brand commitments (v4.0.0) | Adopted — SKILL.md's Context Gathering Protocol and `cmd-init.md`'s interview cover all three, and `init`'s register question became the visitor-mode question. |
| The staleness check (v4.0.0) and `/impeccable doctor` (`reference/doctor.md`, `doctor.mjs`, `staleness*.mjs`) | Only the **prose** is adopted: SKILL.md's "Drift" section tells the agent to report a v3-shaped `PRODUCT.md` (a `register:` field), a `DESIGN.md` older than the pages it describes, or a brief for a page that no longer exists — once, in one line — and never to repair drift as a side effect of a design task. No scripts, no `doctor` command, no per-week finding cache. |
| The concept roll: `concept-seed.mjs`, 188 reviewed catalog worlds dealt as challengers, the public roll API, ratings-weighted draws, re-roll registers, `serve-question.mjs` browser decision page, comp-led vs code-led `buildPath` toggle (v4.0.0–v4.1.0) | **Not adopted.** It depends on a network roll API plus a served catalog and a locally bound HTTP decision page; `palette.mjs` was accepted only because it is self-contained data + `node:crypto`, and none of this is. Recorded here as an idea worth revisiting only if the catalog can be ported as fully self-contained data with no network. What *is* adopted is the part that needs no service: the seven-candidate derivation discipline (rut = the category default plus its predictable opposite, ≥3 material families), presenting one committed direction rather than a ranked menu, naming what a rejected candidate did better and raising the presented direction to match, and the standing exit to the category standard played straight. The `palette.mjs` brand-seed step stays as the anti-convergence mechanism for new content sets. |
| `scripts/palette.mjs` brand-seed picker (v3.5.0: 129 hand-curated OKLCH seed anchors, each with a mood and composition strategy) | Adopted verbatim as a skill script — it is self-contained data + `node:crypto`, and true random seed selection is the point (agent-picked "random" drifts back to favorites). SKILL.md Setup step 5 teaches it for content sets with no committed brand colors; committed brand colors always win. |
| Comp-first visualization: three rendered compositional options approved before code (`reference/visualize.md`), the shipped asset-producer subagent, prompt sidecars, `approved: true` records | Partially adopted. Pneuma's image generation goes through `scripts/generate_image.mjs` / `edit_image.mjs` (taught in SKILL.md), so `cmd-craft.md` keeps the mock-before-build gate and the "the mock is a spatial contract" build discipline — including the color-by-number check and the correct-the-record-upward rule — but not the sidecar/approval bookkeeping or the parallel producer fan-out. |
| The four shipped subagents (`skill/agents/*`: finish reviewer, documenter, asset producer, manual-edit applier) as harness-native agent files | Not adopted as files. The **behaviors** are ported as instructions: run the finish review as an isolated sub-agent when the backend exposes a Task tool (matching the v3.9.0 critique row), and record `DESIGN.md` from the built page through the `document` command after the last correction lands. |
| `SKILL.src.md` compiled per-harness at build time: `<codex>` / `<claude>` / `<gemini>` provider blocks, `<!-- rule:* -->` eval markers | Pneuma ships one skill text to all backends. Rule markers are stripped. Provider-block content that is model-agnostic in substance (the Codex ghost-card / over-round / sketchy-SVG / stripe / grid-background bans and tracking floor, the Gemini image-hover ban, the Claude cream-rendition warning) is inlined for every backend — the patterns are defects regardless of which model produced them. |
| `Invoke /impeccable` bridge paragraph | Replaced with: "consult the 'Impeccable.style Design Intelligence' section of the pneuma-webcraft skill (SKILL.md)". |
| `STOP and call the AskUserQuestion tool to clarify.` | Templated as `{{ask_instruction}}` (substituted at runtime to "STOP and ask the user using a normal message"). |
| `{{command_prefix}}impeccable <verb>` slash-command invocations | Rewritten as bare `<verb>` (or "the `<verb>` command") — pneuma users invoke from the toolbar, not via a slash prefix. The `{{command_prefix}}` token is stripped. |
| `teach` renamed to `init` in v3.5.0 (`teach` kept as a deprecated alias) | Mirrored — the toolbar command id is `init` (`cmd-init.md`); a typed `teach` is honored as an alias per SKILL.md routing. |
| Deep topic references folded into their commands in v3.5.0, then consolidated again in v4.0.0 (typeset 279 → 80 lines, colorize 257 → 86, clarify 288 → 94, delight 302 → 70, layout 161 → 84, animate 201 → 89, polish 241 → 97, shape 165 → 59) | Mirrored across every command body. `cmd-adapt.md` and `cmd-critique.md` keep their "Reference Material" sections because upstream still carries that depth there; every other folded topic file is gone, and the bodies that upstream shrank in v4.0.0 shrank here by the same delta. |
| No-argument context-aware recommendation menu (`reference/routing.md`, `context-signals.mjs`, `detect.mjs` scan) | Not adopted — webcraft has no bare invocation; commands arrive from the toolbar via `<user-actions>` or by intent routing. The `init` command's closing "recommend next commands" step is ported (it needs no scripts). |
| `npx impeccable detect` deterministic detector (58 rules) + `npx impeccable live` browser overlay + the two-speed design hook for Claude/Codex/Cursor/Copilot (v3.5.0–v4.1.2) | Not adopted — pneuma-webcraft stays on the agent-driven pattern catalog (the ban list in `craft-floor.md`); CSS-checkable detector rules are ported as agent-readable bans instead. Live preview is the iframe in the Pneuma viewer, so a separate "live mode", its helper server, and editor-hook plumbing aren't needed. Consequently `reference/live.md`, `reference/live-setup.md`, `reference/hooks.md`, `reference/doctor.md`, the entire `scripts/live-*` / `hook*` / `detect*.mjs` / `context*.mjs` / `staleness*.mjs` families, and `skill/agents/*` are not ported. |
| Native platform rulebooks and passes: `reference/ios.md`, `reference/android.md`, `reference/audit.native.md`, `reference/adapt.native.md`, platform detection in `init`, the native verify-and-review leg (v4.0.0–v4.1.0) | Not adopted — webcraft renders web pages in an iframe. Where upstream branches on "native → X, web → Y" we port the Y branch, and platform-detection questions are dropped from `init`. |
| Critique dual-sub-agent isolation + `⚠️ DEGRADED` provenance banner (v3.9.0) | Adopted — Assessment A/B run as isolated sub-agents when the backend exposes a Task tool; browser-overlay evidence is replaced by the Pneuma viewer's `capture` action. |
| `reference/codex.md` (v3.1.0 Codex-specific image flow) | Not adopted — Pneuma's image generation goes through `scripts/generate_image.mjs` / `edit_image.mjs`, not Codex's native image subagent. Where upstream branches on "if Codex with native image gen, do X; otherwise Y" we port the Y branch. |
| Skill self-update check (v3.5.0 `UPDATE_AVAILABLE` directive) | Not adopted — Pneuma's own skill-version tracking (`skill-version.json` + launcher update prompt) owns update detection. |
| Monorepo per-app `PRODUCT.md` / `DESIGN.md` resolution (v3.8.0, extended in v4.1.2 with `projectRoots`) | Not adopted — webcraft workspaces are content-set-shaped, not monorepos; context files live at the project root. |
| `PRODUCT.md` + `DESIGN.md` context files (v3.0 successor to `.impeccable.md`) | Either filename is accepted; the `init` command still updates a pre-existing `.impeccable.md` in place for back-compat with existing user workspaces. The `document` command writes the DESIGN.md visual spec from what shipped. |

| `.impeccable/critique/<timestamp>__<slug>.md` snapshot persistence + `ignore.md` (v3.1.0; `IMPECCABLE_CRITIQUE_META` + trend helper in v3.9.x) | Adopted as agent-driven behavior — `critique` speaks the report into the chat first, then writes the snapshot (YAML frontmatter carries `total_score` / `max_score` / `na_heuristics` / `p0_count` / `p1_count`) via the Write tool and reads the recent files back for the trend line; `polish` reads the latest matching snapshot via Read.
