# 把发布从「每月一次」改成「每天都能发」

这是一份提案。先把现在的样子摆出来，再说改什么，最后说为什么值得改。

## 现在是什么样

每个月底的周四晚上发一次版。发布前两天冻结代码，当晚全员待命到凌晨两点。

真出事的时候，没人能第一时间说清是哪个改动引起的——==一次上线塞了一百多个改动==，排查基本靠猜。

## 改三件事

- 频率：每月一次 → 每天多次
- 每次改动量：一百多个 → 一两个
- 回滚：整包退回 → 只退掉那一个

这三件其实是同一件：批量小了，频率自然上得去，回滚也就便宜了。**顺序不能反过来**——只提频率不减批量，等于把凌晨待命从每月一次变成每天一次。

流水线也只有一条，四段：

```graph 流水线
提交 → 自动测试 → 灰度 10% → 全量
灰度 10%: 先放给十分之一的人
```

新加的是灰度那一段。它把「出事」从一次全量事故，降级成 ((十分之一的事故))。

## 有没有效，看一个数

我们在一个团队里试了半年，量的是「从发现问题到恢复」这一段时间：

```chart 恢复时间
x: 第1月 第2月 第3月 第4月 第5月 第6月  (月)
y: 0 .. 240  (分钟)
```

原来的月发节奏半年没什么变化，一直在三个多小时上下：

```chart 恢复时间
+ 月发: 205 198 212 190 201 196
```

改成日发之后，同样的团队、同样的系统，曲线一路往下走：

```chart 恢复时间
+ 日发: 180 120 74 45 31 24
+ mark 日发 @ 第6月 : "24 分钟"
```

半年下来从三个多小时压到二十四分钟，而这半年一次事故都没有多出来。

## 所以这份提案要的是什么

回到最上面那三行——真正要改的只有中间那一行：

@focus "每次改动量"

频率和回滚都是它带出来的。所以这份提案要的不是「发得更勤」这四个字，是让每一次发布都小到不值得开会。

@circle "小到不值得开会"
