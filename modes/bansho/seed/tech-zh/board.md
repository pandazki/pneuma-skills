# 为什么加机器不一定更快

这块板要说清一件事：并行是有天花板的，而且天花板比大多数人以为的低得多。

## 先把那句口头禅立在这里

慢了就加机器。这句话在小规模上几乎总是对的，所以很少有人追问它什么时候不再成立。

把机器数记作 $n$，单机吞吐记作 $T_1$，口头禅的意思是总吞吐等于 $n T_1$：==加一倍机器，快一倍==。

## 第一刀：总有一段跑不并行

@turn

把任何一个任务拆开，里面只有两类工作：一类能摊给更多机器，一类不管来多少机器都得排着队做完。

- 可并行的部分：机器越多摊得越薄
- 串行的部分：加多少机器都不动
- 天花板：由第二类单独决定

设可并行的比例是 $p$，阿姆达尔定律把加速比写成这个样子：

$$S(n) = \frac{1}{(1 - p) + \frac{p}{n}}$$

代两个数进去就够吓人了：$p = 0.95$ 时，机器加到无穷多，加速比也只有 ((20 倍))；哪怕 $p = 0.99$，上限也不过 ((100 倍))。

## 第二刀：机器之间还要互相说话

@turn

阿姆达尔定律其实还算乐观——它假设那段并行的工作彼此不打扰。真实系统里不是这样：机器越多，协调的代价越大。

通用可扩展性定律在分母上多加了一项串扰代价：

$$C(n) = \frac{n}{1 + \alpha(n - 1) + \beta n(n - 1)}$$

$\alpha$ 是排队，大家抢同一份资源；$\beta$ 是相干，每台机器都要跟其他机器对齐状态。**排队只是让曲线变平，相干会让曲线掉头向下。**

## 把两条曲线画在一起

@turn

```chart 加速比
x: 1 2 4 8 16 32 64  (台)
y: 0 .. 20  (倍)
```

先画只算串行占比的那条——它一直在涨，只是越涨越慢：

```chart 加速比
+ 只算串行占比: 1 1.9 3.5 5.9 9.1 12.6 15.4
```

再把相干开销加进去，同一批机器，曲线在中途就开始往回走：

```chart 加速比
+ 加上相干开销: 1 1.9 3.4 5.5 7.6 8.4 7.1
+ mark 加上相干开销 @ 32 : "峰值"
```

@overview

@erase "阿姆达尔定律把加速比写成这个样子"

@turn

## 所以那句口头禅错在哪

两条曲线合起来的结论很不直觉： ((串行占比)) 决定天花板在哪，((相干开销)) 决定曲线什么时候掉头，而 ==机器数本身== 只决定你落在这条曲线的哪一点上。

错的不是结论，是它藏着的两个前提：一是 ((串行段为零))，二是 ((协调不要钱))。
