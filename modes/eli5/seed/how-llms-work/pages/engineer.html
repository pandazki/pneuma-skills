大语言模型内部到底在算什么

一个自回归的下一个 token 预测器：堆叠的 Transformer 解码器层，在超大规模文本上以「预测下一个 token」为目标训练，推理时逐 token 采样输出。下面按这条主线拆开，顺带说清几个最常被略过的地方。

01输入不是字，是 token

模型看不到字符串。文本先经过分词器切成 token —— 用 BPE 或类似的子词算法，从语料里统计出一份几万到十几万条目的词表。切分粒度在字符和词之间：英文常见词通常是一个 token，词缀会被切开；中文常见字大多是一个 token，生僻字和 emoji 可能被拆成多个字节级片段。

这不是实现细节，它会直接影响你：计费按 token、上下文窗口按 token、模型对字符级操作天生不灵（数一个词有几个字母、精确截断到 N 个字符，这类任务它经常算错，因为它看到的根本不是字母）。

03注意力做的事

每个位置把自己的表示投影成三个向量：查询 Q、键 K、值 V。位置 i 用自己的 Q 去和所有位置的 K 做点积，得到一组权重，再按这组权重把各位置的 V 加权求和 —— 也就是「我这个位置，该从上下文的哪些地方取信息」。

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k + M ) V

M 是因果掩码：把所有 j > i 的位置置为 -inf，保证位置 i 只能看到它左边的内容。这一条是「自回归」的全部含义，也是训练能在整条序列上并行、而推理只能一个一个往外吐的根本原因。

多头就是并行做若干组这样的投影再拼接，让不同的头去关注不同类型的关系。计算量上，一次完整前向对长度 n 是 O(n²·d) —— 长上下文真正贵在这里，不在参数量。

位置信息不是加进去就完事。现在主流做法是旋转位置编码（RoPE），把位置以旋转的形式作用在 Q/K 上。它带来的一个实际后果是：模型在训练长度之外的位置上会明显退化，所以「支持 128K 上下文」和「在 128K 上表现和 8K 一样好」是两件不同的事，需要分别验证。

04训练和推理，差别比想象中大

训练推理
序列处理 整条并行。因果掩码保证位置 i 看不到答案，所以一次前向就能对所有位置算 loss。 严格串行。第 t 个 token 是第 t+1 步的输入，无法提前算。
参数 反向传播更新。显存要同时放下参数、梯度和优化器状态。 完全冻结。你这次调用不会改变模型的任何一个权重。
输入来源 teacher forcing —— 喂的是真实的下一个 token，不是模型自己上一步的输出。 喂的是模型自己刚生成的 token。错误会顺着往下累积。
主要开销 算力。一次预训练是集群规模、以周计的作业。 显存带宽。逐 token 生成阶段通常是访存受限，不是算力受限。

KV cache：推理端最重要的一个优化

朴素实现每生成一个 token 都要把整条序列重算一遍，代价 O(n²·d)。但历史位置的 K 和 V 不会变（因果掩码保证了这点），所以把它们缓存下来，每步只算新 token 的 Q 与全部 K/V 的注意力，单步降到 O(n·d)。

代价是显存：缓存大小正比于 层数 × KV 头数 × 头维度 × 序列长度 × 批量。长上下文的高并发服务里，KV cache 常常比模型权重还占地方 —— GQA、MQA 这些做法就是冲着压这一项去的。

# 自回归生成的骨架，省掉了批处理与停止条件
def generate(model, prompt_ids, max_new_tokens, temperature=0.7, top_p=0.9):
    ids, cache = prompt_ids, None
    for _ in range(max_new_tokens):
        # 首次传完整 prompt（prefill），之后每次只传最后一个 token
        step_in = ids if cache is None else ids[:, -1:]
        logits, cache = model(step_in, kv_cache=cache)

        logits = logits[:, -1, :] / temperature   # 只取最后一个位置
        probs  = softmax(logits)
        probs  = nucleus_filter(probs, top_p)        # 截掉概率尾巴

        nxt = sample(probs)
        ids = cat([ids, nxt], dim=-1)
    return ids

注意 logits[:, -1, :] 这一行：模型对每个位置都算了分布，但生成时只用最后一个。训练时用的恰恰是被丢掉的那些 —— 同一次前向，两种用法。

05预训练之后还有一大半

只做完预训练的模型是个「续写机」，你问它问题，它可能给你再编三个类似的问题出来。把它变成会对话、会守规矩的助手，靠的是后训练：

  • 监督微调（SFT） —— 在人写的「指令 → 期望回答」样本上继续训练，教会它「被问了就该答」这种格式。
  • 偏好优化 —— 收集同一个提示下多个回答的人类排序，用 RLHF 或 DPO 一类方法把模型往被偏好的方向推。有用性、无害性、语气，主要在这一步成形。

一个有用的分工判断：预训练决定它知道什么，后训练决定它怎么表现。所以「模型不肯做某件事」和「模型不会做某件事」是两个完全不同的问题，排查方向也完全不同。

06采样、确定性，以及幻觉

模型输出的是词表上的一个概率分布，选哪个 token 是采样策略的事。temperature 缩放 logits：越低分布越尖、越保守；越高越发散。top_p（核采样）只在累积概率达到 p 的那部分候选里采。

把 temperature 设成 0 也不等于可复现。它退化成贪心解码，但服务端的批处理组合、GPU 上并行归约的浮点加法顺序、不同的 kernel 实现，都会让 logits 在末位上抖动，而两个概率接近的候选一旦因此换位，后面整条路径就分叉了。要可复现，得靠固定输出格式、缓存和校验，别指望采样参数。

幻觉也从这里看得最清楚。训练目标是「在给定上文时，最大化真实下一个 token 的似然」—— 这个目标里没有任何一项在衡量「这句话是不是真的」。当上下文里没有足够信息时，模型不会空着，它会补一个在分布上最像样的续写，而且流畅度和它说对时完全一样。

所以工程上能做的不是「让它别编」，而是把它需要的事实放进上下文（检索增强）、让输出可校验（结构化格式 + 解析校验 + 引用溯源）、在高风险处保留人。这三条是绕开机制，不是修复机制。

07取舍一览

做法换来什么代价
拉长上下文 能一次塞进更多材料，少做切分和拼接 注意力开销随长度平方增长，KV cache 显存线性增长；而且长上下文中段的信息更容易被忽略，得实测而不是假设
换更大的模型 推理质量、长链条任务的稳定性明显更好 单价和延迟都上去了；很多任务上小模型加好提示词就够，先测再换
检索增强（RAG） 把私有和最新的事实喂进去，答案可溯源 检索质量成了新的上限；召回错了，模型会非常自信地基于错材料作答
微调 稳定输出风格和格式，压缩提示词长度 需要数据和评测；灌事实知识效果通常不如检索，且换基座就得重来
调低 temperature 输出更收敛、更可控 创造性任务上变得乏味重复；而且如上所述，并不能换来严格可复现
同一个主题的其他层级：「产品经理」那一级讲能力边界、成本和风险；「8 岁孩子」那一级用词语接龙讲同一件事。
