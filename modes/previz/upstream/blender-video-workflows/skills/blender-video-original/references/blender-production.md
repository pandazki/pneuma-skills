# Blender 制作与验收

## 执行与文件
先探测 Blender、视频探测/编码工具、可用 Computer Use 或 Blender 接口。用户指定 Computer Use 时先读其可用 skill；遵守该工具的交互限制。未指定时可用 Blender Python 批处理提高可靠性。用户说“不输出代码”时不在回复展示代码；若明确禁止脚本，则只用允许的界面工具。后台运行与界面控制能力以实际环境为准，不承诺界面自动化永远不占用前台。
保存可编辑 scene.blend、预览、白模视频、提示词及验收记录到本次独立输出目录；已有成品另存版本，避免覆盖唯一副本。

## 动画
先按秒确定动作段落，再按目标帧率换算。总帧数为时长乘帧率；例如 8 秒、24fps 输出 192 帧，使用 1–192 帧，不额外输出第 193 帧。
人物根节点负责位移，四肢负责相对运动，步幅与根节点速度匹配。行走时左腿前摆配右臂前摆、右腿前摆配左臂前摆；不能把左右同侧手脚设成相同相位。支撑脚接地期间减少世界坐标漂移；停止时将步态平滑收敛，再过渡到抬手动作。
模型有骨骼时优先使用 IK/脚部约束；几何简模可分层父子关节，但不能用持续漂浮的身体替代迈步。检查足底与地面、双腿、手与设备、头与门框的距离。允许接触，不允许明显穿透。
触发事件由手接近按钮的时刻驱动；装置亮度从该帧以后渐增，不能提前亮起。采用蓝色发光材质即可表达触发，不强依赖复杂辉光后处理。
镜头缓慢移动并平滑减速，避免插值过冲。默认最后约 0.5 秒保持镜头和主要动作稳定；用户要求持续运动时服从其设定。

## 渲染与验证
几何白模、无贴图、简单照明；必要的灰度和柔和阴影帮助识别体积。蓝色等叙事强调色仅在剧情需要时使用。按用户设定输出；未指定可用 8 秒、1920×1080、24fps，并在计划中标注为默认值。
先低分辨率渲染完整时间轴，检查至少一个完整步态周期、启停过渡、手部触发前后与结尾。关键截图无法证明无抖动；需要播放或逐帧检查相邻帧。发现顺拐修相位，滑步修速度/足锁，穿模修轨迹/关节，抖动修重复关键帧、约束切换或插值。
预览通过后正式渲染；长渲染优先输出 PNG 序列方便断点续跑，再编码为 MP4/H.264、yuv420p。用实际工具探测编码、尺寸、帧率、帧数和时长，并完整解码检查损坏帧。编码成功不代表动作通过验收。
仅修改受影响部分。连续两轮修改仍出现同一缺陷时，保存当前版本，说明失败片段及原因，避免无限渲染。

## 验收记录
记录输出路径、目标/实际时长、分辨率、帧率、已检查的动作区间、发现和修复的问题、仍存在的限制。未实际播放或检查的项目写“未验证”，不得写全部通过。
